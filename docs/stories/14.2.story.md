# Story 14.2: Genetic Inheritance Migration

**Epic:** Epic 14 - Egg System & Breeding Mechanics  
**Status:** Ready for Done 
**Created:** September 29, 2025  
**Assigned:** Genetic Inheritance Engineering Team  

## Story Statement
As a **genetic inheritance engineer**,  
I want **Pokemon genetic inheritance systems migrated to stateless AO process**,  
so that **genetic trait passing and probability maintain identical mathematical behavior**.

## Acceptance Criteria
1. IV inheritance algorithms produce statistically identical distribution patterns
2. Nature inheritance probability maintains identical parent selection and outcome determination
3. Ability inheritance calculations maintain identical probability distributions and selection logic
4. Hidden ability passing rates maintain identical probability calculation and inheritance behavior
5. Genetic trait combination maintains identical interaction resolution and final outcome calculation
6. Breeding item effects maintain identical modifier application and genetic influence behavior
7. Complex genetic scenarios maintain identical inheritance calculation and probability resolution
8. Comprehensive testing validates 100% genetic inheritance system mathematical and probability parity

## Dev Notes

### Previous Story Insights
- Story 14.1 completed Breeding Compatibility Migration with comprehensive breeding compatibility validation and cross-process coordination patterns
- Critical lessons: Monolithic design with embedded data, direct error handling without excessive pcall usage, proper AO message coordination with other processes
- Established coordination patterns: `breeding-compatibility-engine.lua` handles compatibility validation, `pokemon-instance-manager.lua` manages individual Pokemon instances, `pc-storage-manager.lua` handles breeding pair access
- Process size constraints: Target ~35-45KB based on similar complexity processes (within 500KB limit)
- **DISCOVERY**: Genetic inheritance requires coordination with existing processes: `breeding-compatibility-engine.lua` for breeding pair validation, `pokemon-instance-manager.lua` for parent Pokemon data, `pokemon-species-db.lua` embedded data for inheritance parameters
- **REFERENCE SOURCE**: TypeScript implementation contains comprehensive genetic algorithms (`typescript-reference/src/data/pokemon-data.ts`, `typescript-reference/src/data/nature.ts`, `typescript-reference/src/data/ability.ts`) - genetic inheritance algorithms will maintain mathematical precision identical to TypeScript implementation
- **PARITY APPROACH**: All genetic calculations must match TypeScript behavior exactly with identical probability distributions, IV inheritance patterns, nature passing rates, and ability inheritance logic
- Testing validation patterns established: Unit tests with aolite, integration tests with aos-local, parity tests against TypeScript implementation, AO sandbox compliance validation
- Cross-process coordination requires actual ao.send() calls with proper Target, Action, Data structure

### Component Specifications

#### GeneticInheritance Core Component [Source: architecture/components.md#Game State Coordinator]
- **Purpose**: Complete genetic inheritance calculation with TypeScript mathematical parity
- **Dependencies**: Embedded genetic algorithms, Pokemon instance validation, species genetic data
- **Key Methods**: `calculateIvInheritance()`, `determineNatureInheritance()`, `calculateAbilityInheritance()`, `processCompleteInheritance()`
- **State Management**: Immutable genetic state updates through deep copy operations
- **Error Handling**: Direct error responses via ao.send() without pcall wrapping of simple operations

#### IV Inheritance Calculator Component
- **Purpose**: Individual Value inheritance calculation with mathematical precision
- **Implementation**: Deterministic inheritance algorithm matching TypeScript behavior exactly
- **Key Methods**: `calculateIvInheritance()`, `processDestinyKnotEffect()`, `applyPowerItemEffects()`
- **Mathematical Precision**: Exact probability calculations for inheritance patterns
- **Special Cases**: Destiny Knot mechanics, Power Item guaranteed inheritance, random IV generation

#### Nature Inheritance Processor Component
- **Purpose**: Nature inheritance determination with item effect processing
- **Calculation Types**: Standard inheritance, Everstone effects, dual Everstone scenarios
- **Key Methods**: `determineNatureInheritance()`, `processEverstoneEffect()`, `calculateNatureEffects()`
- **Mathematical Precision**: Exact probability calculations matching TypeScript implementation
- **Constraint Enforcement**: Nature inheritance probability boundaries and item effects

#### Ability Inheritance Calculator Component
- **Purpose**: Ability inheritance calculation including hidden ability mechanics
- **Ability Logic**: Standard ability inheritance, hidden ability passing, ability slot distribution
- **Key Methods**: `calculateAbilityInheritance()`, `processHiddenAbilityInheritance()`, `determineAbilitySlot()`
- **Probability Calculations**: Exact inheritance rate calculations for all ability scenarios
- **Special Handling**: Hidden ability 60% inheritance rate, Ditto ability inheritance, ability slot priority

#### Breeding Item Processor Component
- **Purpose**: Breeding item effect calculation and conflict resolution
- **Item Types**: Destiny Knot, Everstone, Power Items, Oval Charm effects
- **Key Methods**: `validateBreedingItems()`, `processItemEffects()`, `resolveItemConflicts()`
- **Effect Processing**: Comprehensive item effect application and priority resolution
- **Conflict Resolution**: Power Item override of Destiny Knot, item compatibility validation

#### Genetic Optimization Engine
- **Purpose**: Breeding strategy optimization and probability analysis
- **Analysis Types**: Competitive viability, breeding efficiency, multi-generation planning
- **Key Methods**: `optimizeBreedingStrategy()`, `calculateBreedingProbabilities()`, `generateRecommendations()`
- **Strategic Planning**: Multi-generation breeding chain optimization
- **Efficiency Calculation**: Success rate analysis and breeding attempt estimation

#### Cross-Process Coordinator
- **Purpose**: Message-based coordination with Pokemon, Breeding Compatibility, and Species Database processes
- **Message Validation**: Input sanitization and genetic operation authorization
- **State Synchronization**: Real-time genetic state updates based on Pokemon changes
- **Save Integration**: Automatic save data updates for genetic state changes
- **Event Processing**: Asynchronous event handling for genetic calculations and optimizations
