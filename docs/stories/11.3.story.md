# Story 11.3: Temporary vs Permanent Form Migration

**Epic:** Epic 11 - Dynamic Form Change System  
**Status:** Done  
**Created:** September 27, 2025  
**Assigned:** Form Persistence Engineering Team  

## Story Statement
As a **form persistence engineer**,  
I want **temporary and permanent form change systems migrated to stateless AO process**,  
so that **form change duration and persistence maintain identical state management behavior**.

## Acceptance Criteria
1. Temporary form change duration tracking maintains identical expiration logic and timing
2. Permanent form change persistence maintains identical state across all game scenarios
3. Form change reversion conditions evaluate identically to TypeScript implementation
4. Form change state persistence maintains identical data integrity during save/load operations
5. Form change interaction with other systems maintains identical priority and resolution order
6. Form change cancellation mechanics maintain identical trigger conditions and override behavior
7. Complex form change scenarios maintain identical state transition and management logic
8. Comprehensive testing validates 100% form persistence system behavioral parity

### Specific Temporary vs Permanent Form Examples
- **Temporary Battle Forms**: Form changes that last only during battle [Source: src/data/pokemon-forms.ts:weather-based forms]
  - Castform weather forms: Revert when weather changes or battle ends
  - Rotom appliance forms: Persist until form change item used
  - Darmanitan Zen Mode: Triggered by HP threshold, reverts when HP restored
- **Permanent Evolution Forms**: Form changes that persist across all scenarios [Source: src/data/pokemon-forms.ts:evolution-based]
  - Dialga/Palkia Origin Forms: Permanent when holding Adamant/Lustrous Orb
  - Giratina Origin Form: Permanent when holding Griseous Orb or in Distortion World
  - Kyurem Black/White: Permanent fusion until separation item used
- **Conditional Temporary Forms**: Forms with complex duration rules [Source: src/data/pokemon-forms.ts:conditional-forms]
  - Mega Evolution: Battle-only, reverts at battle end
  - Primal Reversion: Battle-only, triggered by item, reverts at battle end
  - Deerling/Sawsbuck: Seasonal forms, persist until season changes
- **Save/Load Persistence Examples**:
  - Sky Forme Shaymin: Permanent during day, reverts to Land at night or when frozen
  - Hoopa Unbound: 3-day timer, reverts to Confined after time expires
  - Necrozma fused forms: Permanent until separation, persists through save/load

6. **Implement save/load form persistence** (AC: 4, 7)
   - Create save/load persistence matching TypeScript patterns:
     ```lua
     function persistFormThroughSave(pokemon, gameState)
         local formData = pokemon.formPersistenceData
         if not formData or not formData.persistThroughSave then
             -- Revert non-persistent forms before save
             revertToBaseForm(pokemon)
             return
         end
         
         -- Validate persistent form data
         if validateFormPersistence(pokemon, formData) then
             gameState.persistentForms = gameState.persistentForms or {}
             gameState.persistentForms[pokemon.id] = {
                 form = pokemon.currentForm,
                 persistenceData = formData,
                 timestamp = getCurrentTime()
             }
         end
     end
     
     function restoreFormFromSave(pokemon, gameState)
         local persistentForms = gameState.persistentForms or {}
         local savedForm = persistentForms[pokemon.id]
         
         if savedForm and validateFormRestoration(pokemon, savedForm) then
             pokemon.currentForm = savedForm.form
             pokemon.formPersistenceData = savedForm.persistenceData
             
             -- Check if form expired during save
             checkFormExpirationOnLoad(pokemon, savedForm.timestamp)
         end
     end
     ```

         -- Priority order: Permanent > Temporary > Conditional > Battle-only
