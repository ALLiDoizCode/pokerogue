### Pokeball and Capture Mechanics Analysis

#### Core Capture System Components [Source: TypeScript codebase analysis and existing capture-engine.lua]

**1. Capture Rate Formula and Calculations**
- **Base Capture Rate Formula**: `((3*maxHP - 2*currentHP) * speciesCatchRate * ballMultiplier) / (3*maxHP)`
- **Critical Capture Formula**: Modified success rate with enhanced shake probability
- **Shake Count Calculation**: Deterministic shake count based on capture probability
- **Success Determination**: Final probability calculation with all modifiers applied

**2. Pokeball Type Effectiveness**
- **Standard Pokeballs**: Poke Ball (1x), Great Ball (1.5x), Ultra Ball (2x), Master Ball (guaranteed capture - bypasses all calculations)
- **Specialty Pokeballs**: Net Ball (3.5x vs Bug/Water), Timer Ball (1x-4x based on turn count), Repeat Ball (3.5x vs caught species)
- **Situational Pokeballs**: Dive Ball (3.5x underwater), Dusk Ball (3.5x caves/night), Quick Ball (5x first turn only)
- **Conditional Effectiveness**: Love Ball (8x opposite gender), Level Ball (2x-8x based on level difference), Heavy Ball (weight-based modifiers)

**3. Pokemon Health and Status Effect Modifiers**
- **Health-Based Capture**: Lower HP = higher capture rate, using exact TypeScript HP percentage calculations
- **Status Effect Modifiers**: Sleep/Freeze (2.5x), Paralysis/Poison/Burn (1.5x), no modifier for other conditions
- **Status Interaction**: Status effects stack multiplicatively with Pokeball modifiers
- **Health Validation**: HP must be within valid range (1 to maxHP) for accurate calculations

**4. Critical Capture Mechanics**
- **Critical Capture Rate**: Base probability modified by Pokedex completion percentage
- **Critical Success Rate**: Enhanced probability calculation when critical capture triggers
- **Shake Behavior**: Critical captures have different shake count patterns
- **Animation Timing**: Critical captures affect battle flow and result display

**5. Capture Animation and Shake Calculations**
- **Shake Count Formula**: `floor(65536 * sqrt(sqrt(255/captureRate))) / 65536`
- **Shake Success Probability**: Each shake has independent success probability
- **Animation Duration**: Shake count affects total capture attempt duration
- **Break-out Mechanics**: Failed shakes result in Pokemon escape with specific probabilities

**6. Failed Capture Behavior and Item Consumption**
- **Pokeball Consumption**: All Pokeballs consumed on capture attempt (success or failure)
- **Pokemon Behavior**: Wild Pokemon may flee, attack, or continue battle after failed capture
- **Flee Probability**: Based on species flee rate, battle duration, and intimidation effects
- **Status Preservation**: Status effects and HP remain after failed capture attempts

**7. Ability and Item Interactions**
- **Capture-Affecting Abilities**: Pressure (reduces catch rate), Magic Guard (blocks status effects)
- **Player Abilities**: Compound Eyes (increased critical capture rate), others affecting success probability
- **Held Item Modifiers**: Items that affect capture rates or status application
- **Ability Stacking**: Multiple abilities can affect capture calculations simultaneously

### Process Coordination Architecture

#### Cross-Process Communication Pattern
```lua
-- Coordination with existing processes
local function coordinateCaptureAttempt(captureData)
    -- 1. Validate Pokemon state with pokemon-instance-manager.lua
    local pokemonResult = ao.send({
        Target = POKEMON_INSTANCE_MANAGER_ID,
        Action = "ValidatePokemon",
        PokemonId = captureData.pokemonId,
        Operation = "status_check",
        Data = json.encode({
            battleId = captureData.battleId,
            validateHP = true,
            validateStatus = true
        })
    })
    
    -- 2. Get battle context from battle-engine.lua
    local battleResult = ao.send({
        Target = BATTLE_ENGINE_ID,
        Action = "QueryBattleState",
        BattleId = captureData.battleId,
        Data = json.encode({
            queryType = "capture_context",
            turnInfo = true,
            environmentalConditions = true
        })
    })
    
    -- 3. Update inventory after ball consumption
    ao.send({
        Target = INVENTORY_MANAGER_ID,
        Action = "ConsumeItem",
        ItemType = captureData.pokeballType,
        Quantity = "1",
        PlayerId = captureData.playerId,
        Data = json.encode({
            reason = "pokeball_usage",
            battleId = captureData.battleId
        })
    })
    
    -- 4. If successful, transfer Pokemon to player collection
    if captureData.success then
        ao.send({
            Target = POKEMON_INSTANCE_MANAGER_ID,
            Action = "TransferPokemon",
            PokemonId = captureData.pokemonId,
            Operation = "wild_to_player",
            PlayerId = captureData.playerId,
            Data = json.encode({
                captureMethod = captureData.pokeballType,
                captureLocation = captureData.battleId,
                captureDate = captureData.timestamp
            })
        })
    end
end
```

- `ao.send()` - Message transmission to other processes

- `Handlers` - Message routing system

- Nature multipliers must be exactly 0.9, 1.0, or 1.1 - never approximate
- All AO message responses must include success boolean
- Never hardcode Pokemon/Move/Item data - always reference database tables
