**Epic:** 1 - Stateless AO Process Foundation & Architecture  
**Status:** Done

## Story Statement
As a **data architecture engineer**,
I want **specialized data processes for game reference data**,
so that **Pokemon, moves, items, and abilities data can be served with optimal performance**.

## Acceptance Criteria
1. Data process template provides pure reference data queries without GameState modification
2. Pokemon species database process serves complete species data with <500KB constraint
3. Moves database process provides move data with type effectiveness integration
4. Items database process serves item data with effect descriptions and mechanics
5. Abilities database process provides ability data with trigger conditions and effects
6. External data referencing optimizes bundle size through Arweave transaction storage
7. Data process response times achieve sub-100ms for reference queries
8. Comprehensive testing validates data accuracy and query performance

### Data Models
**Pokemon Model**: Complete Pokemon representation with stats, moves, abilities, and battle data. Key attributes include speciesId, level, exp, hp, maxHp, stats array, ivs, nature, moveset, statusEffect, abilities, heldItem, battleData [Source: architecture/data-models.md#pokemon-model]

**Species Database Structure**: Embedded Lua tables containing speciesId, name, baseStats array [HP, ATK, DEF, SPATK, SPDEF, SPD], types array, abilities array [normal, hidden], height, weight, evolutionChain object, levelMoves table [Source: architecture/database-schema-embedded-lua-data-structures.md#species-database-schema]

**Stateless Data Flow**: Data processes provide pure reference data queries without modifying GameState, maintaining complete stateless design [Source: architecture/high-level-architecture.md#stateless-process-pattern]

### API Specifications
**Data Process Query Protocol**:
- Request format: `{"Action": "GetSpecies|GetMove|GetItem|GetAbility", "Data": {"id": "identifier"}, "Timestamp": number}`
- Response format: `{"Action": "SaveState", "Data": {requestedData}, "Timestamp": number, "ProcessId": "string"}`
- Error format: `{"Action": "SaveState", "Error": "error message", "ProcessId": "string", "Timestamp": number}`
- All data processes must respond within 100ms for optimal performance [Source: architecture/high-level-architecture.md#generic-response-pattern]

**Process Communication Flow**: 
- Data processes receive queries from coordinator-process.lua via AO message passing
- No direct process-to-process communication between data processes
- All responses use uniform "SaveState" action for client compatibility
- Message validation at process entry points before data retrieval [Source: architecture/tech-stack.md#message-coordination]

**Fixed Process Addresses**:
- pokemon-species-db: Fixed AO process address in topology-config.lua
- moves-database: Fixed AO process address in topology-config.lua  
- items-database: Fixed AO process address in topology-config.lua
- abilities-database: Fixed AO process address in topology-config.lua
[Source: architecture/tech-stack.md#process-discovery]

### Component Specifications
**Data Process Architecture**: Pure reference data processes providing specialized queries without GameState modification. Each process embeds complete dataset in Lua tables with indexing for sub-millisecond lookups [Source: architecture/high-level-architecture.md#data-processes]

**Pokemon State Manager Dependencies**: Species database for base stats and evolution trees, Nature system for stat multipliers (exact 0.9/1.1 values), embedded species data using in-process Lua tables [Source: architecture/components.md#pokemon-state-manager]

**Battle Resolution Handler Dependencies**: Move database for power, accuracy, and effect definitions, Type effectiveness matrix for damage multipliers [Source: architecture/components.md#battle-resolution-handler]

**Query Response Handler Pattern**: State queries for agents and UI systems with JSON responses, sub-100ms response requirement for data queries [Source: architecture/components.md#query-response-handler]

### Technical Constraints
**Size Constraints**: Each data process must remain under 500KB. Use aggressive data compression, abbreviated keys, and external references for oversized segments [Source: architecture/tech-stack.md#size-validation]

**Stateless Design Requirement**: Data processes must not maintain any persistent state. Each query is independent with no side effects [Source: architecture/high-level-architecture.md#stateless-design]

**Embedded Data Storage**: All data stored as Lua tables directly in process files. No external database connections or file I/O operations [Source: architecture/tech-stack.md row for Data Storage]

**Deterministic Responses**: All queries for same input must return identical output. No random elements in data retrieval [Source: architecture/coding-standards.md line 5]

### Security Requirements
**Input Validation**: 
- Implement validateInput(message) function checking Action, Data, Timestamp fields
- Whitelist approach for allowed query types (GetSpecies, GetMove, GetItem, GetAbility)
- Sanitize all identifier inputs to prevent injection attacks
- Reject malformed JSON or missing required fields [Source: architecture/security.md#input-validation]

**Rate Limiting Implementation**:
- Maximum 100 queries per address per minute per process
- Implement rate limiting counter in each data process
- Return SaveState with rate limit error when exceeded [Source: Story 1.1 security requirements]

**Data Integrity**:
- No data modification allowed in data processes
- Read-only operations ensure data consistency
- Validate requested IDs exist before returning data
- Return appropriate error for non-existent data requests [Source: architecture/security.md#game-state-integrity]

### Performance Requirements
**Query Response Times**: <100ms for all data queries measured at process level [Source: Epic 1 Story 1.2 AC7]

**Process-to-Process Latency**: <500ms average latency for coordinator-to-data-process communication [Source: architecture/high-level-architecture.md line 114]

**Concurrent Operations**: Support 1000+ concurrent queries across all data processes [Source: Epic 1 Story 1.4 AC1]

### Coding Standards Compliance
- Never hardcode Pokemon/Move/Item data outside database processes [Source: architecture/coding-standards.md line 9]
- Use camelCase for functions: `getSpeciesData()`, `queryMoveDatabase()` [Source: architecture/coding-standards.md#naming-conventions]
- Use PascalCase for table names: `SpeciesDatabase`, `MoveDatabase` [Source: architecture/coding-standards.md#naming-conventions]
- Files use kebab-case: `pokemon-species-db.lua`, `moves-database.lua` [Source: architecture/coding-standards.md#naming-conventions]

The remaining 4 data processes (type-effectiveness-db, biome-data-db, trainer-data-db, wave-data-db) will be implemented in future stories as the system scales.
