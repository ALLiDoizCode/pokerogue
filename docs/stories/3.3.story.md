## Story Statement
As a **game mechanics engineer**,  
I want **Pokemon abilities and nature systems migrated to stateless AO process**,  
so that **ability effects and nature stat modifications maintain identical functionality**.

## Acceptance Criteria
1. All Pokemon abilities implemented with identical triggers, effects, and interactions as TypeScript
2. Nature stat modifications produce mathematically identical stat calculations
3. Ability interaction chains (ability triggering other abilities) maintain identical behavior
4. Hidden ability assignment and availability matches TypeScript implementation exactly
5. Ability state tracking during battles maintains identical persistence and timing
6. Nature personality generation produces identical probability distributions
7. Complex ability interactions (weather, status, type changes) maintain complete parity
8. Comprehensive testing validates 100% ability and nature behavioral parity

### Data Models
**Ability Data Structure** [Source: architecture/data-models.md#Pokemon Model]:
```lua
AbilityData = {
  -- Basic ability information
  abilityId = number,              -- Unique ability identifier from enums
  name = string,                   -- Ability name (e.g., "Overgrow", "Blaze")
  description = string,            -- Ability description text
  
  -- Trigger and effect data
  triggers = table,                -- Array of trigger conditions
  effects = table,                 -- Array of ability effects
  priority = number,               -- Effect application priority
  
  -- Battle integration
  battleEffects = table,           -- Battle-specific effect modifications
  statModifiers = table,           -- Stat modification effects
  typeInteractions = table,        -- Type effectiveness modifications
  
  -- Availability and constraints
  availability = string,           -- "NORMAL", "HIDDEN", "EVENT"
  cooldown = number,               -- Cooldown between activations (if any)
  usageLimit = number,             -- Maximum uses per battle (if any)
  
  -- Interaction data
  interactionChains = table,       -- Abilities that can trigger from this one
  exclusions = table               -- Abilities that cannot coexist
}
```

**Nature Data Structure** [Source: architecture/data-models.md#Pokemon Model]:
```lua
NatureData = {
  -- Basic nature information
  natureId = number,               -- Nature identifier from enums
  name = string,                   -- Nature name (e.g., "Adamant", "Modest")
  
  -- Stat modifications
  increasedStat = string,          -- Stat with +10% modifier ("attack", "defense", etc.)
  decreasedStat = string,          -- Stat with -10% modifier ("attack", "defense", etc.)
  
  -- Personality and flavor data
  personalityValue = number,       -- 32-bit personality calculation seed
  flavorPreferences = table,       -- Berry flavor preferences
  
  -- Stat multiplier calculations
  getMultiplier = function(stat),  -- Returns 0.9, 1.0, or 1.1 for given stat
  
  -- Battle integration
  battlePersonality = table        -- Battle behavior modifications (future feature)
}
```

### Process Implementation Requirements
**AO Process Constraints** [Source: architecture/tech-stack.md#Process Implementation Requirements]:
- Monolithic Design: All dependencies embedded in single file, no require() statements
- Handler Pattern: Use Handlers.add() with tag matching, not direct assignment
- Error Handling: All operations wrapped in pcall with structured error responses
- Size Limit: 500KB maximum per process file
- Execution Timeout: 5-second limit per message handler

**AO Globals Available** [Source: architecture/tech-stack.md#Available AO Globals]:
- `ao.send()` - Message transmission to other processes
- `ao.id` - Process identifier
- `Handlers` - Message routing with Handlers.add(name, matcher, handler)
- `json` - Data serialization for encode/decode
- Standard Lua: string, table, math, os (limited subset)

### API Specifications
**Handler Message Schemas**:

```lua
-- ApplyNature Handler
Request: {
  Action = "ApplyNature",
  Data = {
    pokemonId = number,           -- Pokemon instance ID
    natureId = number,            -- Nature ID (optional, random if not provided)
    forceNature = string          -- Force specific nature (optional, testing only)
  },
  Timestamp = number
}
Response: {
  Action = "NatureApplied",
  Data = {
    success = boolean,
    pokemonId = number,
    nature = NatureData,          -- Complete nature information
    statModifiers = table,        -- Applied stat multipliers
    error = string (on failure)
  }
}

-- TriggerAbility Handler
Request: {
  Action = "TriggerAbility",
  Data = {
    pokemonId = number,           -- Pokemon with ability
    abilityId = number,           -- Ability to trigger
    battleContext = table,        -- Battle state context
    triggerEvent = string         -- Event that triggered ability
  },
  Timestamp = number
}
Response: {
  Action = "AbilityTriggered",
  Data = {
    success = boolean,
    pokemonId = number,
    abilityId = number,
    effects = table,              -- Applied effects
    chainTriggers = table,        -- Additional abilities triggered
    error = string (on failure)
  }
}

-- AssignAbility Handler
Request: {
  Action = "AssignAbility",
  Data = {
    pokemonId = number,           -- Pokemon instance ID
    abilitySlot = number,         -- Ability slot (1=normal, 2=normal, 3=hidden)
    forceAbility = number         -- Force specific ability (optional, testing only)
  },
  Timestamp = number
}
Response: {
  Action = "AbilityAssigned",
  Data = {
    success = boolean,
    pokemonId = number,
    ability = AbilityData,        -- Complete ability information
    slot = number,                -- Assigned slot
    error = string (on failure)
  }
}

-- GetAbilityInfo Handler
Request: {
  Action = "GetAbilityInfo",
  Data = {
    abilityId = number            -- Ability ID to query
  },
  Timestamp = number
}
Response: {
  Action = "AbilityInfo",
  Data = {
    success = boolean,
    ability = AbilityData,        -- Complete ability data
    error = string (on failure)
  }
}

-- GetNatureInfo Handler
Request: {
  Action = "GetNatureInfo",
  Data = {
    natureId = number             -- Nature ID to query
  },
  Timestamp = number
}
Response: {
  Action = "NatureInfo",
  Data = {
    success = boolean,
    nature = NatureData,          -- Complete nature data
    error = string (on failure)
  }
}
```

### Technical Constraints
**Coding Standards** [Source: architecture/coding-standards.md]:
- Never use Lua's math.random() - ALWAYS use AO crypto module
- All stat calculations must match TypeScript Math.floor/Math.ceil exactly
- Nature multipliers must be exactly 0.9, 1.0, or 1.1 - never approximate
- All AO message responses must include success boolean
- Never hardcode Pokemon/Move/Item data - always reference database tables
- Battle RNG counter must increment for every random call

**Performance Constraints** [Source: architecture/tech-stack.md#Performance Constraints]:
- Execution Timeout: 5-second limit per message handler
- File Size Limit: 500KB maximum per process file
- Memory Constraints: Limited by AO network specifications
- CPU Cycles: Bounded computational resources per execution
- Message Size: Practical limits on JSON payload size

### Security Requirements
1. **Input Validation**: All ability and nature operations must validate input parameters for type, range, and business logic constraints
2. **Data Integrity**: Ability and nature data must include checksums to prevent corruption during serialization/deserialization
3. **State Consistency**: Ability and nature modifications must be atomic to prevent partial updates
4. **Rate Limiting**: Process should handle rapid ability operations without memory leaks or performance degradation
5. **Access Control**: Ability and nature assignments should be owned by specific player addresses with proper authorization
6. **Data Sanitization**: All ability and nature custom data must be sanitized to prevent injection attacks
7. **Deterministic Behavior**: All random operations must use AO crypto module for reproducible results
