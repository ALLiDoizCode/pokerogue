### Algorithm Specification

#### Matchup Score Calculation (getMatchupScore - lines 2557-2629)
**Purpose**: Evaluate how favorable a Pokemon matchup is against an opponent

**Input**:
```lua
{
    thisPokemon = {
        types = {9}, -- Fire type
        moveset = {{moveId = 52, pp = 10, maxPp = 10}, ...}, -- Ember, etc.
        hp = 80,
        maxHp = 100,
        stats = {atk = 52, def = 43, spatk = 60, spdef = 50, spd = 65},
        isActive = true
    },
    opponent = {
        types = {11, 3}, -- Water/Flying
        hp = 100,
        maxHp = 100,
        stats = {atk = 60, def = 55, spatk = 85, spdef = 70, spd = 90}
    }
}
```

**Algorithm Steps**:

1. **Speed Comparison** (lines 2560-2562)
   - Compare effective speed stats
   - `outspeed = thisPokemon.speed >= opponent.speed`
   - If active, use getEffectiveStat() to account for stat modifiers

2. **Defense Score Calculation** (lines 2568-2572)
   - Base: `defScore = 1 / max(type_effectiveness_against_us, 0.25)`
   - For dual-type opponents: multiply by second type effectiveness
   - Range: 0.25 (quad weak) to 4.0 (quad resist)
   - Formula: `defScore = (1 / eff1) * (1 / eff2)`

3. **Attack Score Calculation** (lines 2574-2601)
   - For each damaging move with PP > 0:
     - Calculate type effectiveness against opponent
     - Apply STAB multiplier (1.5x) if move type matches Pokemon type
     - Skip moves with VariableMoveTypeAttr
   - Average all attack scores: `atkScore = sum / move_count`
   - Default to 1.0 if no damaging moves available

4. **HP Ratio Analysis** (lines 2607-2628)
   - Base ratio: `hpDiffRatio = myHP% + (1 - oppHP%)`
   - **Dying Pokemon (HP <= 20%)**:
     - Check if bad matchup: `atkScore < 1.5 && defScore < 1.5`
     - If slow and bad matchup: multiply by 0.85 (sacrifice candidate)
     - Otherwise: `hpDiffRatio = 1 - myHP% + (outspeed ? 0.2 : 0.1)`
   - **Outspeeding**: multiply by 1.25
   - **Moderate HP (20-40%)**: multiply by 0.5 (switch candidate)

5. **Final Score** (line 2629)
   - `matchupScore = (atkScore + defScore) * min(hpDiffRatio, 1)`
   - Typical range: 0-16, maximum possible: 64

**Key Insight**: Low HP Pokemon (20-40%) are penalized to encourage switching

#### Party Member Matchup Scoring (getPartyMemberMatchupScores - lines 559-592)
**Purpose**: Score all available party members for switching consideration

**Algorithm Steps**:

1. **Filter Available Party Members** (lines 565-568)
   - Skip already-fielded Pokemon (indices 0-1 for doubles, 0 for singles)
   - Skip fainted Pokemon (`isAllowedInBattle()` returns false)
   - Filter by trainer slot if doubles battle

2. **Calculate Matchup Scores** (lines 569-589)
   - For each available party member:
     - Score against each active player Pokemon
     - If opponent is legendary: divide score by 2
     - Average scores across all opponents
   - If `forSwitch = true`: apply entry hazard penalties

3. **Entry Hazard Penalties** (lines 581-585)
   - Check for Stealth Rock, Spikes, Toxic Spikes, Sticky Web
   - Call `getMatchupScoreMultiplier(pokemon)` for each hazard
   - Multiply matchup score by penalty (e.g., 0.75 for Stealth Rock with 2x weakness)

**Output**: Array of `[partyIndex, matchupScore]` tuples

#### Switch Decision Logic (EnemyCommandPhase - lines 57-87)
**Purpose**: Decide whether to switch Pokemon based on matchup comparison

**Preconditions** (lines 57-60):
- Must have a trainer (wild Pokemon never switch)
- Move queue must be empty (no queued charging moves)
- Pokemon must not be trapped (no Wrap, Mean Look, etc.)

**Algorithm Steps**:

1. **Get Party Member Scores** (line 61)
   - Call `getPartyMemberMatchupScores(trainerSlot, forSwitch=true)`
   - Includes entry hazard penalties

2. **Calculate Current Matchup Score** (lines 64-65)
   - Score against all active player Pokemon
   - Average if multiple opponents (doubles)

3. **Apply Switch Dampening** (line 69)
   - **TypeScript formula**: `1 - Math.pow(0.1, 1 / (enemySwitchCounter || 1))`
   - **Lua translation**: `1 - (0.1 ^ (1 / math.max(enemySwitchCounter, 1)))`
   - First switch (counter=1): multiplier = 1.0 (no penalty)
   - Second switch (counter=2): multiplier ≈ 0.68 (strong penalty)
   - Third+ switches (counter=3+): multiplier ≈ 0.36 (severe penalty)
   - Prevents excessive switching back and forth

4. **Compare Best Party Member** (line 71)
   - Boss trainers: switch if `bestScore * multiplier >= currentScore * 2`
   - Normal trainers: switch if `bestScore * multiplier >= currentScore * 3`
   - Higher threshold for normal trainers makes them less likely to switch

5. **Select Switch Target** (line 72)
   - Call `getNextSummonIndex()` with party scores
   - If multiple Pokemon tied for best score: random selection

6. **Execute Switch** (lines 74-83)
   - Set turn command to Command.POKEMON
   - Increment enemySwitchCounter
   - Return early (skip move selection)

**Key Insight**: Switch dampening prevents thrashing while still allowing strategic switches

#### Next Summon Selection (getNextSummonIndex - lines 605-631)
**Purpose**: Select which party member to switch in (handles ties)

**Algorithm Steps**:

1. **Sort Party Scores** (line 613)
   - Descending order by matchup score

2. **Find Maximum Score Pokemon** (lines 615-617)
   - Filter party members with score == best score
   - May be multiple Pokemon tied

3. **Random Selection from Ties** (lines 619-627)
   - Use battle seed with turn offset: `currentBattle.turn << 2`
   - `rand = randSeedInt(maxScorePartyMemberIndexes.length)`
   - Return randomly selected index from tied Pokemon

**Output**: Party index (0-5) of Pokemon to switch in
