### Algorithm Specification

#### Target Selection Flow (getNextTargets - lines 6717-6796)
**Phase 1: Get Potential Targets**
1. Call `getMoveTargets(user, moveId)` to get target set and multi-target flag
2. Filter targets to only active Pokemon matching target indexes

**Phase 2: Multi-Target Detection**
3. If `moveTargets.multiple === true`: return ALL target battler indexes immediately
   - Example moves: Earthquake, Surf, Discharge (hit all enemies)
   - No benefit scoring needed for AoE moves

**Phase 3: Single-Target Benefit Scoring** (lines 6731-6741)
4. For each potential target, calculate benefit score:
   - Call `move.getTargetBenefitScore(attacker, target, move)`
   - Multiply by -1 if target is ally (inverts score for healing/buff moves)
   - Formula: `score * (target.isPlayer() === attacker.isPlayer() ? 1 : -1)`
5. Sort benefit scores descending (highest score first)

**Phase 4: Counter Move Special Case** (lines 6743-6751)
6. If no valid targets and move has CounterDamageAttr:
   - Return `[BattlerIndex.ATTACKER]` (special value -1)
7. If no valid targets: return empty array

**Phase 5: Weight Normalization** (lines 6753-6767)
8. Extract benefit scores as target weights
9. If lowest weight < 1: add `abs(lowestWeight - 1)` to all weights (normalize to positive)
10. Apply cutoff: remove targets with weight < (maxWeight / 2) from consideration

**Phase 6: Probabilistic Selection** (lines 6769-6795)
11. Build cumulative weight thresholds (running total of weights)
12. Generate random value: `randBattleSeedInt(totalWeight)`
13. Select first target where cumulative weight > random value
14. Return single target battler index

**Key Insight**: Target selection is probabilistic weighted by benefit scores, not deterministic "best target"

#### Double Battle and Ally Targeting
**Double Battle Detection**: Check if `opponents.length > 1` or `ally !== nil`

**Ally Targeting Logic** (from move-utils.ts:70-126):
- **Opponent-only moves** (NEAR_ENEMY, ALL_ENEMIES): `set = opponents`
- **Ally-inclusive moves** (OTHER, ALL_OTHERS): `set = opponents.concat([ally])`
- **Ally-only moves** (NEAR_ALLY, ALLY): `set = [ally]`
- **Self-only moves** (USER, PARTY): `set = [user]`
- **Everyone** (ALL, BOTH_SIDES): `set = [user, ally].concat(opponents)`

**Ally Benefit Score Inversion** (line 6733):
- Attacking ally: score × 1 (negative = bad, don't target)
- Healing ally: score × -1 (positive = good, target)
- Formula checks: `target.isPlayer() === attacker.isPlayer()` (same side)

### API Specifications

#### Handler: EvaluateMoveSelection (Enhanced)
**Input Message**:
```lua
{
    Action = "EvaluateMoveSelection",
    Data = json.encode({
        attacker = {battlerIndex, types, level, moves, ...},
        opponents = {{battlerIndex, hp, types, ...}, ...},
        ally = {battlerIndex, hp, types, ...}, -- Optional
        aiType = 2, -- SMART
        battleSeed = 12345
    })
}
```

**Processing**:
1. For each move, call `getNextTargets(moveId)` to get target indexes
2. Calculate move benefit scores for each target
3. Apply AI type selection logic (RANDOM, SMART_RANDOM, SMART)
4. Return selected move ID and target index(es)

**Output Message**:
```lua
{
    Target = msg.From,
    Action = "SaveState",
    Data = json.encode({
        selectedMove = 123,
        targetIndexes = {2},
        benefitScore = 15.5,
        aiType = 2
    })
}
```

### Key Implementation Insights (Technical Deep Dive)

**1. Ally Score Inversion (Lines 1061-1064)**
```lua
local isSameSide = (targetPokemon.isPlayer == attacker.isPlayer)
if isSameSide then
    score = score * -1
end
```
- **Why**: Benefit scores are damage-oriented (positive = good for attacks)
- **Problem**: Healing/buff moves targeting allies should prioritize low HP, but damage scoring gives high scores to high HP targets
- **Solution**: Invert score for same-side targets, making negative scores desirable
- **Result**: AI correctly prioritizes weak allies for healing, strong enemies for attacks

**2. Weight Normalization (Lines 1091-1097)**
```lua
if lowestWeight < 1 then
    local adjustment = math.abs(lowestWeight - 1)
    for i = 1, #targetWeights do
        targetWeights[i] = targetWeights[i] + adjustment
    end
end
```
- **Why**: Negative benefit scores (healing allies, type disadvantages) can produce weights < 1
- **Problem**: Probabilistic selection requires positive weights for distribution
- **Solution**: Shift all weights up by adding abs(lowestWeight - 1)
- **Result**: Maintains relative weight ratios while ensuring positive values

**3. Probabilistic Selection (Lines 1129-1149)**
```lua
local thresholds = {}
local totalWeight = 0
for _, weight in ipairs(targetWeights) do
    totalWeight = totalWeight + weight
    table.insert(thresholds, totalWeight)
end

local randValue = seed % math.floor(totalWeight)
for i, threshold in ipairs(thresholds) do
    if randValue < threshold then
        targetIndex = i
        break
    end
end
```
- **Why**: AI should be smart but not perfectly optimal (predictable and exploitable)
- **How**: Cumulative weight thresholds create probability distribution
- **Example**: Weights [15.5, 8.2] → Thresholds [15.5, 23.7] → 65% chance first, 35% second
- **Result**: Best targets more likely, but weaker targets still possible

**4. Multi-Target Optimization (Line 1025)**
```lua
if moveTargets.multiple then
    return targetIndexes  -- Return all targets for AoE moves
end
```
- **Why**: AoE moves (Earthquake, Surf) hit all targets regardless of benefit scores
- **Optimization**: Skip expensive benefit scoring for multi-target moves
- **Impact**: Significant performance gain for common moves
- **Result**: <200ms execution even for complex double battles

**5. Battle Seed Determinism (Lines 910, 1139)**
```lua
local seed = tonumber(battleSeed) or 0
local randomIndex = (seed % #opponents) + 1  -- RANDOM_NEAR_ENEMY
local randValue = seed % math.floor(totalWeight)  -- Probabilistic selection
```
- **Why**: Reproducible AI behavior for testing and debugging
- **How**: Battle seed from message data drives all random operations
- **Benefit**: Same state + same seed = same selection (parity testing possible)
- **Result**: 100% deterministic execution, enabling exact TypeScript comparison
