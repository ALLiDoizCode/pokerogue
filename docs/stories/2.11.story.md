### State Isolation Strategy

**Critical Pattern from Story 2.8/2.9**: Use unique entity IDs for test isolation.

**Entity ID Patterns by Process:**

1. **seasonal-event-engine** (Event Species Tests):
   ```lua
   -- Use unique EventId per test scenario
   sendMessage("TrackEventSpeciesEncounter", {
       SpeciesId = "GIMMIGHOUL",
       EventId = "test-event-species-1"  -- Unique per test
   })
   ```

2. **narrative-state-engine** (Narrative Tests):
   ```lua
   -- Use unique NarrativeId or EncounterId per test
   sendMessage("ValidateNarrativeProgress", {
       EncounterId = "test-encounter-1",  -- Unique per test
       NarrativeId = "test-narrative-1"
   })
   ```

3. **fusion-content-engine** (Fusion Tests):
   ```lua
   -- Use unique FusionId or Pokemon IDs per test
   sendMessage("GenerateFusionName", {
       BaseSpeciesId = "25",
       FusionSpeciesId = "26",
       FusionId = "test-fusion-1"  -- Unique per test
   })
   ```

**Why This Matters**: Processes maintain state across message calls. Without unique IDs, tests accumulate state and fail on precise value assertions.

### Consolidated Process Testing Pattern

**Challenge**: Multiple test files target a single consolidated process with many handlers.

**Solution**: Handler-specific testing with clear handler targeting:

```lua
-- event-species-collection.test.lua (targets tracking handlers)
print("📝 Test 1: Track event species encounter")
local response1 = sendMessage("TrackEventSpeciesEncounter", {
    SpeciesId = "GIMMIGHOUL",
    EventId = "test-event-1"
})

-- event-species-generation.test.lua (targets generation handlers, SAME process)
print("📝 Test 1: Generate event species")
local response2 = sendMessage("GenerateEventSpecies", {
    EventId = "test-event-2"  -- Different EventId for isolation
})
```

**Key Principle**: Each test file focuses on specific handlers within the consolidated process.
