### Integration Testing Approach
This story implements a **custom integration testing framework** that simulates AO environment behavior for deployment validation. The framework extends the existing `testing/aos-local/integration-test-framework.js` and uses aolite for process emulation rather than real aos-local, as the project requires controlled testing environments that can be automated in CI/CD pipelines. [Source: Project requirements and existing testing infrastructure]

### Process Implementation Requirements
- **Monolithic Design**: All dependencies embedded in single file, no require() statements [Source: architecture/tech-stack.md#Process Implementation Requirements]
- **Handler Pattern**: Use `Handlers.add()` with tag matching, not direct assignment [Source: architecture/tech-stack.md#Process Implementation Requirements]
- **Error Handling**: All operations wrapped in pcall with structured error responses [Source: architecture/tech-stack.md#Process Implementation Requirements]
- **Performance Monitoring**: Built-in timeout detection and execution time tracking [Source: architecture/tech-stack.md#Process Implementation Requirements]
- **Deterministic Execution**: Seeded RNG, no process-local randomness or external I/O [Source: architecture/tech-stack.md#Process Implementation Requirements]

### Available AO Globals
- `ao.send()` - Message transmission to other processes [Source: architecture/tech-stack.md#Available AO Globals]
- `ao.id` - Process identifier for debugging [Source: architecture/tech-stack.md#Available AO Globals]
- `Handlers` - Message routing with `Handlers.add(name, matcher, handler)` [Source: architecture/tech-stack.md#Available AO Globals]
- `json` - Data serialization for message data and GameState objects [Source: architecture/tech-stack.md#Available AO Globals]
- Standard Lua: string, table, math, os (limited subset) [Source: architecture/tech-stack.md#Available AO Globals]
