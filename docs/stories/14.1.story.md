# Story 14.1: Breeding Compatibility Migration

**Epic:** Epic 14 - Egg System & Breeding Mechanics  
**Status:** Done 
**Created:** January 5, 2025  
**Assigned:** Breeding System Engineering Team  

## Story Statement
As a **breeding system engineer**,  
I want **Pokemon breeding compatibility systems migrated to stateless AO process**,  
so that **breeding pair validation and success rates maintain identical behavior to TypeScript**.

## Acceptance Criteria
1. Breeding compatibility algorithms evaluate identically for all Pokemon species combinations
2. Egg group validation maintains identical constraint checking and compatibility determination
3. Breeding success rate calculations produce mathematically identical probabilities
4. Gender ratio considerations maintain identical breeding pair selection and success logic
5. Special breeding conditions maintain identical trigger evaluation and requirement validation
6. Breeding time calculations maintain identical duration and completion timing
7. Breeding restriction enforcement maintains identical constraint validation and error handling
8. Comprehensive testing validates 100% breeding compatibility system behavioral parity

- Testing validation patterns established: Unit tests with aolite, integration tests with aos-local, parity tests against Pokemon game mechanics, AO sandbox compliance validation
- Cross-process coordination requires actual ao.send() calls with proper Target, Action, Data structure

### Technical Constraints [Source: architecture/tech-stack.md, coding-standards.md]

**AO Runtime Requirements**:
- **Monolithic Design**: All dependencies embedded in single file, no require() statements
- **Handler Pattern**: Use `Handlers.add()` with tag matching, not direct assignment
- **Error Handling**: Direct error handling with ao.send() responses, avoid unnecessary pcall usage for simple operations
- **Performance**: 5-second execution timeout, 500KB file size limit
- **Deterministic Execution**: Use msg.Timestamp, no os.time() or math.random() calls

**Available AO Globals**:
- `ao.send()` - Message transmission to other processes
- `ao.id` - Process identifier
- `Handlers` - Message routing system
- `json` - Data serialization for cross-process communication
- Standard Lua: string, table, math (limited subset)

**Mandatory Behavioral Parity Rules** [Source: architecture/coding-standards.md]:
- Never use Lua's math.random() - ALWAYS use AO crypto module for deterministic randomness when needed
- All breeding calculations must match TypeScript behavior exactly
- Never hardcode Pokemon data - always reference through Pokemon instance manager
- All AO message responses must include success boolean
- Breeding state changes must trigger save data updates
- Compatibility algorithms must be mathematically identical to TypeScript implementation
