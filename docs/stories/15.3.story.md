# Story 15.3: Achievement-Based Progression Migration

**Epic:** Epic 15 - Passive Abilities & Unlockables
**Status:** Done
**Created:** September 30, 2025
**Assigned:** Achievement System Engineering Team

## Story Statement
As a **achievement system engineer**,
I want **achievement-based progression systems migrated to stateless AO process**,
so that **achievement tracking and rewards maintain identical calculation and distribution behavior**.

## Acceptance Criteria
1. Achievement progress tracking maintains identical data accumulation and milestone detection
2. Achievement completion detection maintains identical trigger condition evaluation and validation
3. Achievement reward calculation maintains identical point distribution and bonus allocation
4. Achievement category organization maintains identical grouping and progression logic
5. Achievement sharing and export maintains identical data formatting and accessibility
6. Achievement reset and progression maintains identical state management and preservation behavior
7. Complex achievement scenarios maintain identical progress calculation and completion determination
8. Comprehensive testing validates 100% achievement system tracking and reward parity

## Dev Notes

### Previous Story Insights
- Story 15.2 completed Unlockable Content Migration with `unlockable-content-engine.lua` handling 4 simple unlockables
- Critical lessons from Stories 15.1-15.2:
  - Monolithic design with all dependencies embedded (no require() statements except json)
  - Error handling: Direct validation with ao.send() error responses, avoid unnecessary pcall
  - Proper AO message coordination using ao.send() with structured Target, Action, Data
  - Process size targets: 10-15KB for simple processes, 35-45KB for complex logic, 70-80KB for large embedded data
  - ADP v1.0 compliance required with Info handler for self-documentation
  - Tag-based message parameters for simple values, Data field for complex structures
  - Avoid module-level returns - use message passing exclusively
  - All tag values MUST be strings: tostring(number), "true"/"false" for booleans
  - Timestamp handling: CRITICAL - Use msg.Timestamp, NEVER os.time()
- **COMPLEXITY ASSESSMENT**: Achievement system is significantly more complex than unlockables:
  - 68 total achievements vs 4 unlockables
  - Multiple achievement categories with specialized validation logic
  - Type-based batch validation system
  - Integration with voucher system for rewards
  - Dynamic condition evaluation with custom validation functions
  - Achievement tier calculation based on score thresholds
  - Secret achievements with parent-child relationships
- **REFERENCE SOURCE**: TypeScript implementation spans multiple files:
  - `typescript-reference/src/system/achv.ts` - Core achievement system (895 lines)
  - `typescript-reference/src/battle-scene.ts` - Achievement validation logic (lines 3272-3293)
  - `typescript-reference/src/system/game-data.ts` - Achievement state tracking (AchvUnlocks interface)
  - `typescript-reference/src/system/voucher.ts` - Voucher reward integration
- **PARITY APPROACH**: All achievement validation logic must match TypeScript validateAchv/validateAchvs behavior exactly
- Testing validation patterns: Unit tests with aolite, integration tests with aos-local, parity tests against TypeScript

#### Achievement Tiers
[Source: typescript-reference/src/system/achv.ts#L22-28, L89-103]
```lua
local AchvTier = {
    COMMON = 0,   -- score < 25
    GREAT = 1,    -- score >= 25 and < 50
    ULTRA = 2,    -- score >= 50 and < 75
    ROGUE = 3,    -- score >= 75 and < 100
    MASTER = 4    -- score >= 100
}

-- Tier calculation function
local function getTier(score)
    if score >= 100 then return AchvTier.MASTER end
    if score >= 75 then return AchvTier.ROGUE end
    if score >= 50 then return AchvTier.ULTRA end
    if score >= 25 then return AchvTier.GREAT end
    return AchvTier.COMMON
end
```

    Action = "ValidateAchievementsByType",
    PlayerId = "player_456",

    Args = json.encode([1250])

-- Step 3: Achievement engine validates and returns results
achievement-engine -> coordinator-process {
    Action = "AchievementsBatchValidated",

            { id = "_1000_DMG", score = 25, timestamp = 1234567890000 }
        },
        totalNewUnlocks = 1
    })
}

-- Step 4: Coordinator updates player progression
coordinator-process -> player-progression-engine {
    Action = "UpdateAchievements",
    PlayerId = "player_456",
    AchievementData = json.encode({...})

-- Step 5: State persistence confirmation
player-progression-engine -> coordinator-process {
    Action = "AchievementsUpdated",
    Success = "true"
}

coordinator-process -> notification-engine {

### Technical Constraints
[Source: architecture/tech-stack.md]
- **Execution Timeout**: 5-second limit per message handler
- **File Size Limit**: 500KB maximum per process file (target 70-80KB for 68 achievements)
- **Monolithic Design**: All 68 achievements embedded, no external imports except json
- **Handler Pattern**: Use Handlers.add() with tag matching, not direct assignment
- **Message Protocol**: JSON-encoded data with structured ao.send() responses
- **Timestamp Handling**: CRITICAL - Use msg.Timestamp, NEVER os.time()
- **Error Handling**: Direct validation with ao.send() error responses, avoid unnecessary pcall
- **Large Data Structure**: 68 achievements with metadata and validation functions
- **Tag Values**: All tag values MUST be strings: tostring(number), "true"/"false" for booleans

### Security Requirements
- **Input Validation**: All player IDs and achievement IDs must be validated before processing
- **Authorization**: Player can only query/modify their own achievement state
- **State Integrity**: Ensure achievement unlock timestamps cannot be forged or manipulated
- **Validation Integrity**: Achievement conditions must be validated server-side, not client-reported
- **Idempotency**: Multiple validation calls for same achievement should be safe (already unlocked = no-op)
- **Secret Achievement Protection**: Secret achievements should not be visible until unlocked or parent unlocked

- Following established pattern from Epic 15 Stories 15.1-15.2
