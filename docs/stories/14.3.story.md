# Story 14.3: Egg Move and Learning Migration

**Epic:** Epic 14 - Egg System & Breeding Mechanics  
**Status:** Done 
**Created:** September 29, 2025  
**Assigned:** Egg Move Engineering Team  

## Story Statement
As a **egg move engineer**,  
I want **egg move inheritance and learning systems migrated to stateless AO process**,  
so that **move passing and learning maintain identical behavior to TypeScript implementation**.

## Acceptance Criteria
1. Egg move inheritance algorithms maintain identical move passing logic and constraint validation
2. Move pool generation maintains identical availability checking and compatibility determination
3. Move learning validation maintains identical constraint checking and requirement evaluation
4. Move priority and selection maintains identical ordering and conflict resolution behavior
5. Special move inheritance conditions maintain identical trigger evaluation and activation logic
6. Move slot management maintains identical space allocation and replacement behavior
7. Complex move inheritance scenarios maintain identical resolution order and final outcome determination
8. Comprehensive testing validates 100% egg move system behavioral and logical parity

## Dev Notes

### Previous Story Insights
- Story 14.1 completed Breeding Compatibility Migration establishing comprehensive cross-process coordination patterns using `breeding-compatibility-engine.lua`
- Story 14.2 completed Genetic Inheritance Migration with `genetic-inheritance-engine.lua` handling IV, nature, ability, and hidden ability inheritance
- Critical lessons from previous stories:
  - Monolithic design with all dependencies embedded (no require() statements except json)
  - Direct error handling without excessive pcall usage (only for genuinely unpredictable operations)
  - Proper AO message coordination between processes using ao.send() with structured Target, Action, Data
  - Process size targets: 35-45KB for complex logic processes (well within 500KB limit)
  - ADP v1.0 compliance required with Info handler for self-documentation
  - Tag-based message parameters for simple values, Data field for complex structures
  - Avoid module-level returns - use message passing exclusively
- **DISCOVERY**: Egg move system requires coordination with multiple existing processes:
  - `breeding-compatibility-engine.lua` - Breeding pair validation and compatibility checks
  - `genetic-inheritance-engine.lua` - Parent Pokemon trait inheritance
  - `pokemon-species-db.lua` - Species egg move data and move pool information
  - `moves-database.lua` - Move data, attributes, and learning requirements
  - `pokemon-instance-manager.lua` - Individual Pokemon move management
- **REFERENCE SOURCE**: TypeScript implementation in `typescript-reference/src/data/balance/egg-moves.ts` contains complete egg move database (900+ species mappings), `typescript-reference/src/data/pokemon-species.ts` contains move learning validation logic
- **PARITY APPROACH**: All egg move inheritance must match TypeScript behavior exactly including move priority, slot management, and special inheritance conditions
- Testing validation patterns: Unit tests with aolite, integration tests with aos-local, parity tests against TypeScript, AO sandbox compliance validation

### API Specifications
No specific REST API endpoints for egg moves as this is a process-to-process communication system. The process will receive and send AO messages with the following structure:

#### Incoming Message Structure [Source: architecture/tech-stack.md#Process Communication Protocol]
```lua
-- Request egg move inheritance (from breeding process)
msg = {
    Action = "InheritEggMoves",
    Parent1Id = "parent1_pokemon_id",
    Parent2Id = "parent2_pokemon_id",
    OffspringSpeciesId = "species_id",
    PlayerId = "player_wallet_address",
    Timestamp = "1234567890"
}

-- Validate move learning
msg = {
    Action = "ValidateMoveLearn",
    PokemonId = "pokemon_instance_id",
    MoveId = "move_to_learn",
    SlotToReplace = "1-4 or nil",
    PlayerId = "player_wallet_address",
    Timestamp = "1234567890"
}

-- Query egg move pool for a species
msg = {
    Action = "GetEggMovePool",
    SpeciesId = "species_id",
    Parent1Id = "parent1_pokemon_id", -- optional
    Parent2Id = "parent2_pokemon_id", -- optional
    PlayerId = "player_wallet_address"
}

-- Manage move slots for a Pokemon
msg = {
    Action = "ManageMoveSlots",
    PokemonId = "pokemon_instance_id",
    Operation = "add|remove|replace|reorder",
    MoveId = "move_id",
    SlotNumber = "1-4",
    PlayerId = "player_wallet_address"
}
```

#### Outgoing Response Structure
```lua
-- Successful egg move inheritance response
ao.send({
    Target = msg.From,
    Action = "SaveState",
    InheritedMoves = json.encode(inheritedMoveList),
    MoveSlots = json.encode(finalMoveSlots),
    Success = "true"
})

-- Egg move pool response
ao.send({
    Target = msg.From,
    Action = "EggMovePool",
    SpeciesId = speciesId,
    Data = json.encode({
        availableMoves = eggMoveList,
        parentMoves = parentContributions,
        priority = movePriority
    })
})

-- Move slot management response
ao.send({
    Target = msg.From,
    Action = "MoveSlotsUpdated",
    PokemonId = pokemonId,
    CurrentMoves = json.encode(currentMoveSlots),
    Success = "true"
})

-- Error response
ao.send({
    Target = msg.From,
    Action = "Error",
    Error = "Move incompatible with species"
})
```

#### Cross-Process Coordination Messages

```lua
-- TO breeding-compatibility-engine.lua: Verify parent compatibility
ao.send({
    Target = BREEDING_COMPATIBILITY_PROCESS_ID,
    Action = "ValidateParents",
    Parent1Id = parent1Id,
    Parent2Id = parent2Id,
    PlayerId = playerId
})

-- FROM breeding-compatibility-engine.lua: Compatibility result
msg = {
    Action = "ParentValidationResult",
    Valid = "true|false",
    EggGroup1 = "egg_group",
    EggGroup2 = "egg_group"
}

-- TO pokemon-species-db.lua: Get species egg moves
ao.send({
    Target = SPECIES_DB_PROCESS_ID,
    Action = "GetSpeciesEggMoves",
    SpeciesId = speciesId
})

-- FROM pokemon-species-db.lua: Species egg moves
msg = {
    Action = "SpeciesEggMoves",
    SpeciesId = "species_id",
    Data = json.encode(eggMoveList)
}

-- TO moves-database.lua: Validate move data
ao.send({
    Target = MOVES_DB_PROCESS_ID,
    Action = "GetMoveData",
    MoveId = moveId
})

-- FROM moves-database.lua: Move data response
msg = {
    Action = "MoveData",
    MoveId = "move_id",
    Data = json.encode(moveData)
}

-- TO pokemon-instance-manager.lua: Update Pokemon moves
ao.send({
    Target = INSTANCE_MANAGER_PROCESS_ID,
    Action = "UpdatePokemonMoves",
    PokemonId = pokemonId,
    Moves = json.encode(newMoveSet),
    PlayerId = playerId
})

-- FROM pokemon-instance-manager.lua: Update confirmation
msg = {
    Action = "MovesUpdated",
    PokemonId = "pokemon_id",
    Success = "true"
}
```

### Technical Constraints [Source: architecture/tech-stack.md]
- **File Size Limit**: 500KB maximum (target ~40KB)

- **Deterministic Behavior**: No randomness in move selection (use passed seeds)

### Security Requirements [Source: architecture/security.md]
- **Input Validation**: Validate all Pokemon IDs, species IDs, and move IDs
- **Authorization**: Verify player owns the Pokemon being modified
- **Data Integrity**: Validate move compatibility with species before inheritance
- **State Consistency**: Ensure move slots remain valid (no duplicates, max 4)

### AO Compliance Requirements [Source: CLAUDE.md#AO Process Implementation Guidelines]
- **Monolithic Design**: Embed all egg move data and logic in single file
- **Handler Pattern**: Use `Handlers.add()` with tag matching for all message handling
- **Error Handling**: Direct validation with ao.send() responses, avoid unnecessary pcall
- **Timestamp Handling**: Use `msg.Timestamp` for any time-based logic
- **No Module Returns**: Do not use module-level return statements
- **Tags vs Data**: Use tags for IDs/flags, Data field for complex move lists
- **ADP v1.0 Compliance**: Include Info handler for self-documentation
