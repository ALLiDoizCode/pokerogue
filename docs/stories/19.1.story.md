### API Specifications

**Process: mystery-encounter-engine.lua**

**Handler: SelectEncounter**
- **Input Tags:** BiomeId, WaveIndex, GameMode, Data (JSON: gameState with party, encountersCompleted)
- **Output Tags:** EncounterType, Success (true/false), Error (if validation fails)
- **Output Data:** JSON encounter definition if selected, null if no valid encounter
- **Purpose:** Select a valid mystery encounter based on biome, wave, and game state

**Handler: ValidateEncounterRequirements**
- **Input Tags:** EncounterType, Data (JSON: gameState)
- **Output Tags:** Valid (true/false), RequirementsPassed (comma-separated list of met requirements), RequirementsFailed (comma-separated list of failed requirements)
- **Purpose:** Validate if an encounter's requirements are met by current game state

**Handler: GetEncountersByBiome**
- **Input Tags:** BiomeId, WaveIndex (optional), GameMode (optional)
- **Output Tags:** EncounterCount (number of valid encounters), Success (true/false)
- **Output Data:** JSON array of valid encounter types for biome
- **Purpose:** Return all encounters valid for a specific biome

**Handler: TrackEncounterCompletion**
- **Input Tags:** EncounterType, Data (JSON: encountersCompleted map)
- **Output Tags:** EncounterCount (updated count for this encounter), AllowedRemaining (max allowed - current count), Blocked (true if maxAllowedEncounters reached)
- **Output Data:** JSON updated encountersCompleted map
- **Purpose:** Update encounter completion tracking and check max limits

**Handler: GetEncounterProbabilities**
- **Input Tags:** BiomeId, WaveIndex, Data (JSON: gameState)
- **Output Tags:** TotalProbability (sum of all weights), EncounterCount (number of eligible encounters)
- **Output Data:** JSON array of {encounterType, probability, tier} objects
- **Purpose:** Calculate spawn probabilities for all valid encounters

**Handler: Info** (ADP v1.0 Compliance)
- **Input Tags:** Action = "Info"
- **Output Tags:** Success = "true"
- **Output Data:** JSON process metadata
- **Purpose:** Self-documentation for ADP v1.0 compliance

**Requirement Validation Pattern:**

TypeScript uses abstract classes with meetsRequirement() methods. Lua implementation:
```lua
local REQUIREMENT_VALIDATORS = {
  WaveRange = function(req, gameState)
    local wave = gameState.waveIndex
    return wave >= req.minWave and wave <= req.maxWave
  end,
  PartySize = function(req, gameState)
    return #gameState.party >= req.minSize
  end,
  -- ... more validators
}

local function validateRequirements(encounter, gameState)
  for _, req in ipairs(encounter.requirements) do
    local validator = REQUIREMENT_VALIDATORS[req.type]
    if not validator(req, gameState) then
      return false
    end
  end
  return true
end
```

**Selection Algorithm:**

TypeScript implementation is in BattleScene.ts, needs to be replicated in Lua:
```lua
local function selectEncounter(biomeId, waveIndex, gameState, seed)
  -- 1. Filter encounters by biome
  local validEncounters = filterEncountersByBiome(biomeId)

  -- 2. Filter by game mode and challenge restrictions
  validEncounters = filterByGameMode(validEncounters, gameState.gameMode)

  -- 3. Filter by requirements (wave, party, etc.)
  validEncounters = filterByRequirements(validEncounters, gameState)

  -- 4. Filter by max encounters limit
  validEncounters = filterByEncounterLimit(validEncounters, gameState.encountersCompleted)

  -- 5. Calculate weighted probabilities by tier
  local probabilities = calculateProbabilities(validEncounters)

  -- 6. Seeded random selection
  return weightedRandomSelection(validEncounters, probabilities, seed)
end
```
