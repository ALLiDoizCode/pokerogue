### API Specifications

**Handler: GetActiveEvent** [Source: Architecture requirements for AO message patterns]
- **Trigger Tag**: `Action = "GetActiveEvent"`
- **Required Parameters**: `msg.Timestamp` (UTC timestamp as string)
- **Response**: Active TimedEvent object or nil if no event active
- **Error Conditions**: Invalid timestamp format
- **Example**:
  ```lua
  -- Request
  {Action = "GetActiveEvent", Timestamp = "1735000000"}

  -- Response
  {
    Action = "SaveState",
    Data = json.encode({
      activeEvent = {name = "Winter Holiday Update", ...}
    }),
    Success = "true"
  }
  ```

**Handler: GetEventMultipliers** [Source: Architecture requirements]
- **Trigger Tag**: `Action = "GetEventMultipliers"`
- **Required Parameters**: `msg.Timestamp`
- **Response**: Multiplier values for shiny, friendship, luck
- **Cumulative Logic**: If multiple events active, multiply shiny values, use max friendship, sum luck
- **Example**:
  ```lua
  {
    Action = "SaveState",
    Data = json.encode({
      shinyMultiplier = 2,
      friendshipMultiplier = 4,
      luckBoost = 1
    })
  }
  ```

**Handler: GetEventEncounters** [Source: src/timed-event-manager.ts:435-445]
- **Trigger Tag**: `Action = "GetEventEncounters"`
- **Required Parameters**: `msg.Timestamp`
- **Response**: Array of EventEncounter objects from all active events
- **Combines**: Multiple active events concatenate their encounter lists
- **Example**:
  ```lua

    Action = "SaveState",
    Data = json.encode({
      encounters = {
        {species = "GIMMIGHOUL", blockEvolution = true, formIndex = nil},
  ```

### Component Specifications

No specific component specifications from architecture documents. This story focuses on data migration and business logic implementation following the stateless AO process pattern.

**Process Structure Pattern** [Source: docs/architecture/tech-stack.md#process-implementation-requirements]
```lua
-- Monolithic design with embedded data
local timedEvents = {...} -- All event data embedded

-- Helper functions
local function parseUTCDate(timestamp) ... end
local function isEventActive(event, currentTime) ... end
local function getActiveEvents(currentTime) ... end

-- Handler registration (individual handlers for each action)
Handlers.add("get-active-event",
  Handlers.utils.hasMatchingTag("Action", "GetActiveEvent"),
  function(msg)
    local timestamp = tonumber(msg.Timestamp)
    if not timestamp then
      ao.send({Target = msg.From, Action = "Error", Error = "Invalid timestamp"})
      return
    end

    local activeEvent = getActiveEvents(timestamp)[1]
    ao.send({
      Target = msg.From,
      Action = "SaveState",
      Data = json.encode({activeEvent = activeEvent}),
      Success = tostring(activeEvent ~= nil)
    })
  end
)
```

### Technical Constraints

**AO Runtime Constraints** [Source: docs/architecture/tech-stack.md#performance-constraints]
- Execution Timeout: 5-second limit per message handler
- File Size Limit: 500KB maximum (estimated 100-150KB for this process)
- Memory Constraints: Limited by AO network specifications
- Deterministic Execution: No os.time(), use msg.Timestamp for all date operations

**AO Compliance Requirements** [Source: docs/architecture/tech-stack.md#process-implementation-requirements]
- Monolithic Design: All event data embedded in single file, no require() statements
- Handler Pattern: Use `Handlers.add()` with individual handlers per action (no multi-action handlers)
- Error Handling: Direct validation and error responses, avoid unnecessary pcall usage
- **CRITICAL**: Never use pcall for simple data access (table lookups, parameter validation)
- **CRITICAL**: Use pcall ONLY for operations that genuinely might fail (external JSON parsing from untrusted sources)
- Available Globals: ao.send(), ao.id, Handlers, json, standard Lua (string, table, math)

**Forbidden Operations** [Source: CLAUDE.md#ao-process-implementation-guidelines]
- `require()` - No external module loading
- `os.time()` - Use `msg.Timestamp` instead
- `io` - No file system access
- `debug` - Debug library unavailable
- Network operations - Only through ao.send()
- Math.random() - Use AO crypto module for deterministic RNG (not applicable for this story)

**Coding Standards** [Source: docs/architecture/coding-standards.md]
- Functions: camelCase (e.g., `isEventActive()`)
- Variables: camelCase (e.g., `activeEvent`, `eventData`)
- Constants: UPPER_SNAKE_CASE (e.g., `DEFAULT_FRIENDSHIP_MULTIPLIER`)
- Tables/Objects: PascalCase (e.g., `TimedEvent`)
- Files: kebab-case (e.g., `seasonal-event-engine.lua`)
- Never use math.random() - N/A for this story (no RNG needed)
- All message responses must include Success tag: `Success = "true"` or `Success = "false"`

**Date Handling Requirements**
- All dates in UTC format: ISO 8601 strings or Unix timestamps
- Use Lua's `os.date("!*t", timestamp)` for UTC parsing
- Compare timestamps as numbers for date range validation
- No timezone conversions (all calculations in UTC)
- Handle date boundary conditions (midnight transitions, month/year rollover)
