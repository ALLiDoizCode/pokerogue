### Architecture Decision: New Integration Process
**Rationale for New Process:**
- Gacha integration requires coordinating 3 separate processes (21.1, 21.2, 21.3)
- Complete gacha pull workflow: voucher redemption → tier rolling → species selection → egg creation
- Balance validation and fairness monitoring require cross-engine statistical analysis
- Stateless orchestration pattern: integration engine coordinates message passing to specialized engines
- Progression integration tracking: hatch waves, advancement milestones, economy impact
- Process size management: estimated ~30-40KB (integration logic, no large embedded data tables)
- Future extensibility: centralized integration point for gacha system enhancements

**Implementation Strategy:**
- Create new `processes/gacha-integration-engine.lua` process
- Implement ExecuteGachaPull handler: orchestrate complete gacha workflow
- Integrate with existing processes: voucher-economy-engine, egg-tier-reward-engine, gacha-mechanics-engine
- Implement balance validation: fairness algorithms, pity effectiveness, outcome distribution
- Implement statistical monitoring: pull history analysis, fairness metrics, anomaly detection
- Maintain stateless design: all data passed via GameState JSON
- Use deterministic execution for predictable gacha outcomes

### API Specifications

**Handler: ExecuteGachaPull** [Source: Architecture requirements for gacha workflow orchestration]
- **Trigger Tag**: `Action = "ExecuteGachaPull"`
- **Required Parameters**: `msg.VoucherType`, `msg.GachaType`, `msg.Data` (JSON with voucher balance, pity counters, dex data)
- **Response**: Complete gacha pull result with egg details and updated state
- **Workflow**: Validate voucher → Roll tier with pity → Select species → Create egg → Update pity/voucher state
- **Integration Points**: voucher-economy-engine, egg-tier-reward-engine
- **Example**:
  ```lua
  -- Request
  {
    Action = "ExecuteGachaPull",
    VoucherType = "2",  -- PREMIUM
    GachaType = "LEGENDARY",
    Data = json.encode({
      voucherCounts = {["0"]=5, ["1"]=3, ["2"]=1, ["3"]=0},
      eggPity = {["0"]=0, ["1"]=7, ["2"]=45, ["3"]=300},

    Action = "SaveState",
  ```

- Monolithic Design: All integration logic in single file
- Handler Pattern: Use `Handlers.add()` with individual handlers per action (no multi-action handlers)
- Error Handling: Direct validation and error responses, avoid unnecessary pcall usage
- **CRITICAL**: Never use pcall for simple data access (table lookups, parameter validation)
- **CRITICAL**: Use pcall ONLY for operations that genuinely might fail (external JSON parsing from untrusted sources)
- Available Globals: ao.send(), ao.id, Handlers, json, standard Lua (string, table, math)

- `require()` - No external module loading (except require("json") which is permitted)
- `os.time()` - Use `msg.Timestamp` instead
- `io` - No file system access
- `debug` - Debug library unavailable
- Network operations - Only through ao.send()

- Tables/Objects: PascalCase (e.g., `GachaType`, `FairnessMetrics`)
- Files: kebab-case (e.g., `gacha-integration-engine.lua`)
- All message responses must include Success tag: `Success = "true"` or `Success = "false"`
