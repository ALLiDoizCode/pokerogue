### TypeScript Reference Implementation
**Core Weather System**: 
- `typescript-reference/src/enums/weather-type.ts` - WeatherType enum (NONE, SUNNY, RAIN, SANDSTORM, HAIL, SNOW, FOG, HEAVY_RAIN, HARSH_SUN, STRONG_WINDS)
- `typescript-reference/src/data/weather.ts` - Weather class with core mechanics
- `typescript-reference/src/phases/weather-effect-phase.ts` - Weather effect execution in battle phases
- Key Features:
  - Turn counting with `turnsLeft` property (decrements each turn, 0 = expired)
  - Immutable weather types: HEAVY_RAIN, HARSH_SUN, STRONG_WINDS (never expire)
  - Damage weather: SANDSTORM (1/16 max HP), HAIL (1/16 max HP) with type immunities
  - Attack type multipliers: SUNNY/HARSH_SUN (Fire +50%, Water -50%), RAIN/HEAVY_RAIN (Fire -50%, Water +50%)
  - Move blocking: HARSH_SUN blocks Water moves, HEAVY_RAIN blocks Fire moves
  - Ability suppression: SuppressWeatherEffectAbAttr can disable weather effects
  - Message system: Start, lapse, damage, clear, and continue messages with i18n keys

### API Specifications
**Message Protocol** [Source: architecture/tech-stack.md#46-68]:
```lua
-- Incoming Message Structure for Weather Operations
msg = {
    Action = "ProcessLogic",
    Data = {
        operation = "setWeather", -- or "processWeatherTurn", "clearWeather", "getWeatherInfo"
        gameState = {
            battle = {
                conditions = { weather = { weatherType = "RAIN", turnsLeft = 5 } },
                playerParty = { /* Pokemon data for damage calculations */ },
                enemyParty = { /* Pokemon data for damage calculations */ }
            },
            battleSeed = "deterministic_seed"
        },
        parameters = {
            weatherType = "RAIN", -- Using TypeScript names: SUNNY, RAIN, SANDSTORM, etc.
            duration = 5, -- turns (0 for immutable weather)
            overwrite = true -- whether to replace existing weather
        }
    },
    Timestamp = msg.Timestamp or 0
}

-- Response Structure with Weather Data
ao.send({
    Target = msg.From,
    Action = "SaveState",
    Data = json.encode({
        success = true,
        weather = {
            weatherType = "RAIN",
            turnsLeft = 4, -- decremented if processed turn
            isActive = true
        },
        effects = {
            damageDealt = 125, -- for damaging weather
            typeMultiplier = 1.5, -- for affected moves
            moveBlocked = false -- for move blocking weather
        },
        messages = {
            "Rain continues to fall!"
        }
    }),
    Error = error_message, -- Optional
    ProcessId = ao.id,
    Timestamp = tostring(msg.Timestamp or 0)
})
```

**Handler Registration Pattern** [Source: CLAUDE.md - AO Process Implementation Guidelines]:
- MUST use individual handlers for each action (no multi-action handlers)
- Use Handlers.add() with tag matching, never direct assignment
- Wrap operations in pcall only when they might fail (not for simple lookups)

**AO Runtime Constraints** [Source: architecture/tech-stack.md#78-84]:
- 5-second execution timeout per handler
- 500KB maximum file size
- No math.random() - use deterministic RNG passed in messages
- No os.time() - use msg.Timestamp for time tracking
- Monolithic design - all code in single file

**Coding Standards** [Source: architecture/coding-standards.md#3-11]:
- Never use math.random() - use AO crypto module
- Match TypeScript Math.floor/Math.ceil exactly
- Include success boolean in all responses
- Reference embedded database tables
- Maintain deterministic behavior for replay capability
