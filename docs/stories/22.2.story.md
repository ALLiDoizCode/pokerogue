- **Required Parameters**: `msg.Data` (JSON with dexData and starterData)
- **Response**: Progress results with completion percentages and milestone status
- **Workflow**: Extract dex data → Count species → Calculate percentages → Detect milestones → Return results
- **Special Cases**: Zero-division protection for empty collections, regional species range mapping

**Process Integration Pattern** [Source: docs/architecture/tech-stack.md#process-communication-protocol]
```lua
-- New collection-statistics-engine.lua process
-- Statistics calculation pattern: consume dex/stats data and generate analytics

local json = require("json")

-- Constants
local MAX_SPECIES_COUNT = 1025

-- Helper functions for calculations
local function calculateCompletionPercentage(caught, total)
  if total == 0 then return 0.0 end
  return (caught / total) * 100.0
end

local function calculateSuccessRate(successes, attempts)
  if attempts == 0 then return 0.0 end
  return successes / attempts
end

-- Handler registration (individual handlers for each action)
Handlers.add("calculate-progress",
  Handlers.utils.hasMatchingTag("Action", "CalculateProgress"),
  function(msg)
    local data = json.decode(msg.Data or "{}")
    if not data.dexData then
      ao.send({
        Target = msg.From,
        Action = "Error",
        Error = "dexData required"
      })
      return
    end

    local progress = calculateProgress(data.dexData, data.starterData)

    ao.send({
      Target = msg.From,
      Action = "SaveState",
      Success = "true",
      Data = json.encode(progress)
    })
  end
)

-- Additional handlers for statistics, analytics, visualization, comparison
```

### Technical Constraints

**AO Runtime Constraints** [Source: docs/architecture/tech-stack.md#performance-constraints]
- Execution Timeout: 5-second limit per message handler
- File Size Limit: 500KB maximum per process file
- Estimated Process Size: ~40-50KB for statistics calculation and analytics
- Memory Constraints: Limited by AO network specifications
- Deterministic Execution: Consistent calculation behavior (no randomness)

**AO Compliance Requirements** [Source: docs/architecture/tech-stack.md#process-implementation-requirements]
- Monolithic Design: All statistics logic in single file
- Handler Pattern: Use `Handlers.add()` with individual handlers per action (no multi-action handlers)
- Error Handling: Direct validation and error responses, avoid unnecessary pcall usage
- **CRITICAL**: Never use pcall for simple data access (table lookups, parameter validation, arithmetic)
- **CRITICAL**: Use pcall ONLY for operations that genuinely might fail (external JSON parsing from untrusted sources)
- Available Globals: ao.send(), ao.id, Handlers, json, standard Lua (string, table, math)

**Forbidden Operations** [Source: CLAUDE.md#ao-process-implementation-guidelines]
- `require()` - No external module loading (except require("json") which is permitted)
- `os.time()` - Use `msg.Timestamp` instead
- `io` - No file system access
- `debug` - Debug library unavailable
- Network operations - Only through ao.send()

**Coding Standards** [Source: docs/architecture/coding-standards.md]
- Functions: camelCase (e.g., `calculateProgress()`, `generateStatistics()`)
- Variables: camelCase (e.g., `completionPercentage`, `captureVelocity`)
- Constants: UPPER_SNAKE_CASE (e.g., `MAX_SPECIES_COUNT`, `DECIMAL_PRECISION`)
- Tables/Objects: PascalCase (e.g., `GameStats`, `ProgressData`)
- Files: kebab-case (e.g., `collection-statistics-engine.lua`)
- All message responses must include Success tag: `Success = "true"` or `Success = "false"`

**Deterministic Behavior Requirements**
- All calculation operations must be predictable and reproducible
- Percentage calculations must be consistent across executions
- Trend analysis must be verifiable and auditable
- Zero-division protection mandatory for all division operations

**Mathematical Precision** [Source: docs/architecture/coding-standards.md]
- Use Lua's native floating-point for percentage calculations
- Maintain precision: round percentages to 2 decimal places (e.g., 45.67%)
- Ensure consistency: identical inputs produce identical outputs
- Validate bounds: percentages must be 0.0 <= x <= 100.0
