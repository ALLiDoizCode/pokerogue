### Architecture Decision: New Standalone Process
**Rationale for New Process:**
- Contextual help is distinct from interactive tutorials (ongoing vs. one-time)
- Help system requires context analysis and relevance calculation
- Separation allows focused testing of help presentation behavior
- Process size management: help logic estimated ~30-40KB with embedded content
- Future extensibility: help system may expand with new help topics and personalization

**Implementation Strategy:**
- Create new `processes/contextual-help-engine.lua` process
- Define help topic constants and content embedded in process
- Implement handlers: GetHelpContent, RecordHelpUsage, GetHelpHistory, ValidateHelpRelevance
- Maintain stateless design with all help state passed via GameState JSON
- Use deterministic context detection for reproducible help behavior

**Process Architecture Pattern** [Source: docs/architecture/tech-stack.md#process-communication-protocol]
```lua
-- New contextual-help-engine.lua process
-- Stateless design with embedded help content

local json = require("json")

-- Help Topic Constants
local HelpTopic = {
  UI_NAVIGATION = "UI_NAVIGATION",
  BATTLE_BASICS = "BATTLE_BASICS",
  POKEMON_INFO = "POKEMON_INFO",
  ABILITY_EXPLANATION = "ABILITY_EXPLANATION",
  TYPE_EFFECTIVENESS = "TYPE_EFFECTIVENESS",
  MOVE_SELECTION = "MOVE_SELECTION",
  ITEM_USAGE = "ITEM_USAGE",
  -- ... (additional help topics)
}

-- Help Content Database (embedded)
local HELP_CONTENT = {
  [HelpTopic.ABILITY_EXPLANATION] = {
    category = "ABILITY",
    title = "Pokémon Abilities",
    content = "Each Pokémon has a unique ability...",
    contextTriggers = {
      uiModes = {"SUMMARY", "PARTY"},
      focusElements = {"pokemon_ability"}
    },
    relevanceThreshold = 0.7,
    priority = 5
  },
  -- ... (other help topics)
}

-- Helper functions for help content retrieval
local function getHelpContent(context, preferences)
  -- Calculate relevance scores for all topics
  local relevantTopics = {}
  for topicId, topic in pairs(HELP_CONTENT) do
    local relevance = calculateRelevance(topic, context)
    if relevance >= topic.relevanceThreshold then
      table.insert(relevantTopics, {
        topicId = topicId,
        topic = topic,
        relevanceScore = relevance
      })
    end
  end

  -- Sort by relevance and priority
  table.sort(relevantTopics, function(a, b)
    if a.relevanceScore == b.relevanceScore then
      return a.topic.priority > b.topic.priority
    end
    return a.relevanceScore > b.relevanceScore
  end)

  -- Return best match
  if #relevantTopics > 0 then
    local best = relevantTopics[1]
    return {
      success = true,
      helpAvailable = true,
      content = {
        topicId = best.topicId,
        title = best.topic.title,
        content = best.topic.content,
        relevanceScore = best.relevanceScore
      }
    }
  end

  return {success = true, helpAvailable = false}
end

-- Handler registration (individual handlers for each action)
Handlers.add("get-help-content",
  Handlers.utils.hasMatchingTag("Action", "GetHelpContent"),
  function(msg)
    local contextData = json.decode(msg.Data or "{}")
    if not contextData.context then
      ao.send({
        Target = msg.From,
        Action = "Error",
        Error = "Context data required"
      })
      return
    end

    local result = getHelpContent(contextData.context, contextData.playerPreferences or {})

    ao.send({
      Target = msg.From,
      Action = "SaveState",
      Success = "true",
      Data = json.encode(result)
    })
  end
)

-- Additional handlers for help usage tracking, history, validation
```

### Technical Constraints

**AO Runtime Constraints** [Source: docs/architecture/tech-stack.md#performance-constraints]
- Execution Timeout: 5-second limit per message handler
- File Size Limit: 500KB maximum per process file
- Estimated Process Size: ~30-40KB for help logic and content
- Memory Constraints: Limited by AO network specifications
- Deterministic Execution: Predictable context detection (no randomness)

**AO Compliance Requirements** [Source: docs/architecture/tech-stack.md#process-implementation-requirements]
- Monolithic Design: All help logic in single file
- Handler Pattern: Use `Handlers.add()` with individual handlers per action (no multi-action handlers)
- Error Handling: Direct validation and error responses, avoid unnecessary pcall usage
- **CRITICAL**: Never use pcall for simple data access (table lookups, parameter validation)
- **CRITICAL**: Use pcall ONLY for operations that genuinely might fail (JSON parsing from untrusted sources)
- Available Globals: ao.send(), ao.id, Handlers, json, standard Lua (string, table, math)

**Forbidden Operations** [Source: CLAUDE.md#ao-process-implementation-guidelines]
- `require()` - No external module loading (except require("json") which is permitted)
- `os.time()` - Use `msg.Timestamp` instead
- `io` - No file system access
- `debug` - Debug library unavailable
- Network operations - Only through ao.send()

**Coding Standards** [Source: docs/architecture/coding-standards.md]
- Functions: camelCase (e.g., `getHelpContent()`, `calculateRelevance()`)
- Variables: camelCase (e.g., `helpContent`, `contextData`)
- Constants: UPPER_SNAKE_CASE (e.g., `HELP_CONTENT`, `DEFAULT_VERBOSITY`)
- Tables/Objects: PascalCase (e.g., `HelpTopic`, `ContextData`)
- Files: kebab-case (e.g., `contextual-help-engine.lua`)
- All message responses must include Success tag: `Success = "true"` or `Success = "false"`

**Deterministic Behavior Requirements**
- All context detection must be predictable and reproducible
- Relevance scoring must be consistent across executions
- Help usage tracking must be accurate and verifiable
- No randomness in help content selection or ranking

**Contextual Help System Flow**
This story focuses on contextual help detection and delivery:
1. **Client Request**: User triggers help (hover, focus, explicit request)
2. **Context Analysis**: Engine analyzes UI mode, game phase, focus element
3. **Relevance Calculation**: Calculate relevance scores for all help topics
4. **Priority Ranking**: Sort topics by relevance and priority
5. **Content Selection**: Return best matching help content
6. **Presentation Metadata**: Include timing, positioning, interruption level
7. **Usage Tracking**: Record help display, interaction, dismissal
8. **Response**: Return help content with presentation metadata

**Key Integration Points**:
- UI system: Tooltip display and positioning (showTooltip, hideTooltip)
- Game state: Help usage statistics and user preferences
- Player progression: Experience level affects help frequency
- Coordinator ensures atomic operations (usage update, preference save)
