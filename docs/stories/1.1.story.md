### API Specifications
**Coordinator Message Protocol**: 
- Async message passing coordination via coordinator-process for complex workflows with operation state tracking
- Message format: `{"Action": "CoordinateOperation", "OperationId": "uuid", "ProcessTargets": ["process-id-1"], "RequestData": {...}}`
- Response format: `{"Action": "SaveState", "OperationId": "uuid", "Data": {...}, "Status": "completed|failed|pending"}` [Source: architecture/tech-stack.md#message-coordination]

**SaveState Protocol Specification**:
- Uniform response action: All processes must respond with `"Action": "SaveState"` regardless of input specificity
- Required response fields: `{"Action": "SaveState", "Data": gameStateOrProcessResult, "Timestamp": number, "ProcessId": "string"}`
- Error format: `{"Action": "SaveState", "Error": "error message", "ProcessId": "string", "Timestamp": number}`
- Client handling: Clients parse `SaveState` responses to extract game state updates or process results

**Process Communication**: 
- AO Messages (JSON) for inter-process communication and orchestration with native AO async message passing
- Message validation: All incoming messages validated against JSON schema before processing
- Error handling: Malformed messages return `SaveState` with error field populated [Source: architecture/tech-stack.md#message-coordination]

**Fixed Process Topology**: 
- Predefined process addresses stored in `processes/topology-config.lua` with no dynamic discovery
- Address format: `{ProcessType: "data|logic|coordinator", ProcessId: "string", Address: "ao-process-id"}`
- Eliminates discovery overhead and enables predictable routing [Source: architecture/tech-stack.md#process-discovery]

### Component Specifications

**Logic Processes**: Pure computation processes (battle-engine, evolution-engine, capture-engine, status-effects-engine) performing GameState transformations [Source: architecture/high-level-architecture.md#logic-processes]

### Technical Constraints
**Stateless Design**: Each process receives complete state, performs computation, returns updated state with no persistent storage within processes [Source: architecture/high-level-architecture.md#stateless-process-pattern]

**Size Constraints**: Each process must remain under 500KB through aggressive code optimization and external data references [Source: architecture/tech-stack.md#size-validation]

**AO Platform**: Lua 5.3+ execution environment with native AO message passing and deterministic processing [Source: architecture/tech-stack.md#process-runtime]

**Fixed Topology**: Predefined process addresses eliminating discovery overhead for predictable message routing [Source: architecture/tech-stack.md#process-discovery]

### Security Requirements
**Input Validation Implementation**:
- Custom Lua validation system with whitelist approach at process entry points
- Validation function: `validateInput(message)` in each process checks required fields, data types, and value ranges
- Reject any message missing required fields: `Action`, `Data`, `Timestamp`
- Validate JSON structure and sanitize all string inputs [Source: architecture/security.md#input-validation]

**Message Authentication Implementation**:
- AO message sender validation using `msg.From` wallet address verification
- Session management: No server-side sessions, each message must include authentication context
- Rate limiting: Maximum 100 messages per address per minute implemented in each process
- Unauthorized access handling: Return `SaveState` with error message for invalid senders [Source: architecture/security.md#authentication-authorization]

**GameState Integrity Implementation**:
- Atomic message processing: Each process validates complete GameState before any modifications
- State validation rules: HP > 0, levels between 1-100, valid Pokemon species IDs, move sets within legal bounds
- Rollback mechanism: Any validation failure prevents GameState modification and returns original state
- Comprehensive validation at process boundaries ensures no partial corruption [Source: architecture/security.md#game-state-integrity]
