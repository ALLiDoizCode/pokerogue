### Component Specifications
[Source: src/field/arena.ts]

**Time of Day Calculator** - `getTimeOfDay(wave, waveCycleOffset, biome)`
- Input: wave (number), waveCycleOffset (number), biome (BiomeId)
- Output: TimeOfDay enum value
- Logic: `waveCycle = (wave + waveCycleOffset) % 40`
  - waveCycle 0-14: DAY
  - waveCycle 15-19: DUSK
  - waveCycle 20-34: NIGHT
  - waveCycle 35-39: DAWN
- Special case: BiomeId.ABYSS always returns NIGHT

**Pool Update Manager** - `updatePoolsForTimeOfDay(biome, timeOfDay, lastTimeOfDay, biomePools)`
- Input: biome (BiomeId), timeOfDay (TimeOfDay), lastTimeOfDay (TimeOfDay), biomePools (table)
- Output: merged pokemon pool, pool updated flag
- Logic:
  1. Check if timeOfDay != lastTimeOfDay (optimization)
  2. Create empty pool for each tier
  3. Copy species from TimeOfDay.ALL
  4. Concatenate species from specific timeOfDay
  5. Return merged pool + true if updated

**Species Form Resolver** - `getSpeciesFormIndex(speciesId, biome, timeOfDay)`
- Input: speciesId (number), biome (BiomeId), timeOfDay (TimeOfDay)
- Output: form index (number)
- Logic:
  - Lycanroc (745): DAY/DAWN → 0, DUSK → 2, NIGHT → 1
  - Burmy/Wormadam (412/413): BEACH → 1, SLUM → 2
  - Rotom (479): VOLCANO → 1, SEA → 2, ICE_CAVE → 3, MOUNTAIN → 4, TALL_GRASS → 5
  - Default: return 0

**Visual Tint Calculator** - `getTintForTimeOfDay(timeOfDay)`
- Input: timeOfDay (TimeOfDay)
- Output: {R, G, B} array
- Logic:
  - DAWN/DAY: {128, 128, 128}
  - DUSK: {113, 88, 100} = [(98+128)/2, (48+128)/2, (73+128)/2]
  - NIGHT: {64, 64, 64}

**Weather Interaction Validator** - `validateWeatherTimeInteraction(weather, timeOfDay)`
- Input: weather (Weather), timeOfDay (TimeOfDay)
- Output: boolean (valid interaction)
- Logic:
  - Weather persists across time changes
  - Time change does not reset weather.turnsLeft
  - Immutable weather (HARSH_SUN, HEAVY_RAIN, STRONG_WINDS) unaffected by time
  - Return true (all interactions valid)

**Transition Detector** - `detectTimeTransition(wave, previousWave, waveCycleOffset)`
- Input: wave (number), previousWave (number), waveCycleOffset (number)
- Output: transition type, milestone reached
- Logic:
  1. Calculate previousCycle and currentCycle
  2. Determine transition boundaries (14→15, 19→20, 34→35, 39→0)
  3. Identify transition type (day_to_dusk, dusk_to_night, night_to_dawn, dawn_to_day)
  4. Check if first occurrence (milestone)

### Technical Constraints

- **Execution Timeout**: 5-second limit per message handler
- **File Size Limit**: 500KB maximum per process file
  - Target: 15-25KB (3-5% of limit) for environmental cycle logic

- **Handler Pattern**: Use `Handlers.add()` with tag matching, one action per handler

- **Message Protocol**: JSON-encoded data with structured ao.send() responses

- Pool update: Expect <200ms execution (array concatenation for 9 tiers)
- Species form resolution: Expect <50ms execution (switch statement lookup)
- Time transition: Expect <150ms execution (change detection + pool update)
- State validation: Expect <100ms execution (comparison logic)
