# Story 8.1: Experience and Leveling Migration

**Epic:** Epic 8 - Player Progression & Experience Systems  
**Status:** Done 
**Created:** September 26, 2025  
**Assigned:** Progression System Engineering Team  

## Story Statement
As a **progression system engineer**,  
I want **Pokemon experience and leveling systems migrated to stateless AO process**,  
so that **experience gain and level progression maintain identical mathematical behavior**.

## Acceptance Criteria
1. Experience calculation formulas produce mathematically identical results for all battle scenarios
2. Experience distribution among party members maintains identical allocation rules
3. Level threshold calculations maintain identical experience requirements for all growth rates
4. Stat increase calculations upon leveling maintain mathematical precision
5. Experience gain modifiers (held items, trainer battles) calculate identically to TypeScript
6. Level cap enforcement and experience overflow maintain identical behavior
7. Experience point display and tracking maintains identical precision and accuracy
8. Comprehensive testing validates 100% experience system mathematical parity

### API Specifications
**Experience Process Message Protocol** [Source: architecture/tech-stack.md#process-communication-protocol]:

**Incoming Message Structure**:
```lua
-- Calculate experience gain
msg = {
    Action = "CalculateExperience",
    DefeatedPokemon = json.encode({...}), -- Pokemon that was defeated
    VictorPokemon = json.encode({...}), -- Pokemon that earned experience
    BattleType = "WILD|TRAINER|GYM", -- Battle context for multipliers
    ParticipatingPokemon = json.encode({...}), -- For EXP share distribution
    Modifiers = json.encode({...}), -- Held items, abilities, etc.
    BattleId = "battle_123",
    Timestamp = "1234567890"
}

-- Apply experience and level up
msg = {
    Action = "ApplyExperience",
    PokemonId = "123",
    ExperienceGained = "2500",
    CurrentExp = "45000",
    CurrentLevel = "35",
    GrowthRate = "MEDIUM_FAST",
    Timestamp = "1234567890"
}

-- Calculate level threshold
msg = {
    Action = "GetLevelThreshold",
    Level = "50",
    GrowthRate = "SLOW|MEDIUM_SLOW|MEDIUM_FAST|FAST|ERRATIC|FLUCTUATING",
    Timestamp = "1234567890"
}

-- Calculate stat increases on level up
msg = {
    Action = "CalculateLevelUpStats",
    Pokemon = json.encode({...}), -- Pokemon data including IVs, EVs, nature
    OldLevel = "35",
    NewLevel = "36",
    SpeciesId = "CHARIZARD",
    Timestamp = "1234567890"
}
```

**Outgoing Response Structure**:
```lua
ao.send({
    Target = msg.From,
    Action = "SaveState",
    Data = json.encode({
        experienceResult = {
            experienceGained = 2500,
            newTotalExp = 47500,
            oldLevel = 35,
            newLevel = 36,
            leveledUp = true,
            statIncreases = {
                hp = 3,
                attack = 2,
                defense = 2,
                spatk = 3,
                spdef = 2,
                speed = 3
            },
            newMoves = {"FLAMETHROWER"}, -- Moves learned on level up
            nextLevelThreshold = 50000
        },
        distributedExperience = {...}, -- For party-wide EXP share
        modifierDetails = {...} -- Applied multipliers breakdown
    }),
    Success = "true",
    ProcessId = ao.id,
    Timestamp = tostring(msg.Timestamp or 0)
})
```

### Technical Constraints
**AO Process Constraints** [Source: architecture/tech-stack.md#performance-constraints]:
- File size limit: 500KB maximum per process file
- Execution timeout: 5-second limit per message handler
- Memory constraints: Limited by AO network specifications
- Deterministic execution: No Math.random, use deterministic formulas only
- Monolithic design: All dependencies embedded, no require() statements

**Performance Requirements**:
- Sub-50ms response time for experience calculation
- Sub-100ms response time for multi-Pokemon experience distribution
- Memory-efficient storage of level threshold tables
- Optimized growth rate formula calculations

**Critical Implementation Notes** [Source: architecture/coding-standards.md]:
- NEVER use Lua's math.random() - experience is deterministic
- All calculations must match TypeScript Math.floor/Math.ceil exactly
- Never hardcode Pokemon/Move/Item data - reference database tables
- All AO message responses must include success boolean
- Use tags for simple parameters (Level, PokemonId), Data field for complex objects

### Project Structure Notes
The experience and leveling engine will be a standalone AO process following the monolithic design pattern established in previous stories. It will communicate with the coordinator process and other battle-related processes through the standard AO message protocol. The process must embed all growth rate formulas and level threshold data to avoid external dependencies.
