### Data Models
**Process Communication Schema** [Source: architecture/tech-stack.md#Process Communication Protocol]:
```lua
-- Incoming Message Structure
msg = {
    Id = "message_id",
    From = "sender_address", 
    Target = "target_process_id",
    Action = "ProcessLogic",
    Data = "json_encoded_data",
    GameState = "json_encoded_gamestate"
}

-- Outgoing Response Structure  
ao.send({
    Target = msg.From,
    Action = "Success|Error",
    Data = json.encode(result_data),
    Error = error_message, -- Optional
    GameState = json.encode(updated_gamestate),
    ProcessId = ao.id,
    Timestamp = tostring(os.time())
})
```

### Technical Constraints
1. **AO Runtime Limitations** [Source: architecture/tech-stack.md#AO Runtime Specifications]:
   - 5-second execution timeout per message handler
   - 500KB file size limit per process
   - No persistent state within processes
   - Limited memory and CPU cycles per execution

2. **26-Process Architecture** [Source: architecture/high-level-architecture.md#Technical Summary]:
   - Coordinator-led orchestration for complex workflows
   - Data processes (pokemon-species-db, moves-database, items-database, abilities-database)
   - Logic processes (battle-engine, evolution-engine, capture-engine, status-effects-engine)
   - Fixed process topology with no dynamic discovery

3. **Message Passing Constraints**:
   - JSON serialization required for all inter-process communication
   - GameState must flow through processes without corruption
   - Async-only communication pattern
   - No direct process-to-process communication (coordinator-mediated)

4. **Performance Requirements**:
   - Multi-process workflows must meet or exceed TypeScript performance
   - Integration tests must complete within CI/CD time limits
   - Memory usage must remain within AO platform constraints

### Security Requirements

### Process Architecture Context
**26-Process Stateless Architecture** [Source: architecture/high-level-architecture.md#High Level Overview]:
- **Data Processes**: pokemon-species-db.lua, moves-database.lua, items-database.lua, abilities-database.lua
- **Logic Processes**: battle-engine.lua, evolution-engine.lua, capture-engine.lua, status-effects-engine.lua
- **Coordinator Process**: coordinator-process.lua (async workflow orchestration)
- **Specialized Processes**: state-validator.lua, query-processor.lua

**Process Communication Flow** [Source: architecture/high-level-architecture.md#Primary Data Flow]:
1. Client sends coordinated request to coordinator-process with GameState
2. Coordinator orchestrates async data collection from specialized data processes
3. Coordinator sends collected data + GameState to appropriate logic process
4. Logic process performs calculations and returns updated GameState
5. Coordinator returns final result to client with updated GameState

**Available AO Globals** [Source: architecture/tech-stack.md#Available AO Globals]:
- `ao.send()` - Message transmission between processes
- `ao.id` - Process identifier for debugging and tracing
- `Handlers` - Message routing with `Handlers.add(name, matcher, handler)` pattern
- `json` - Data serialization for GameState and message data
- Standard Lua: string, table, math, os (limited subset)
