# Story 3.4: IV/EV and Stat Calculation Migration

**Epic:** Epic 3 - Pokemon Data System & Species Management  
**Status:** Done
**Created:** January 25, 2025  
**Assigned:** Development Team  

## Story Statement
As a **stat calculation engineer**,  
I want **IV/EV systems and stat calculations migrated to stateless AO process**,  
so that **all stat computations produce mathematically identical results to TypeScript**.

## Acceptance Criteria
1. IV generation algorithms produce identical probability distributions and value ranges
2. EV training and distribution systems maintain identical mechanics and constraints
3. Stat calculation formulas produce mathematically identical results for all combinations
4. Level-up stat increases maintain identical calculation methodology and outcomes
5. Temporary stat modifications (items, abilities, moves) calculate identically to TypeScript
6. Stat stage modifications (-6 to +6) apply identical multipliers and rounding rules
7. Critical hit and damage calculation dependencies maintain mathematical precision
8. Comprehensive property-based testing validates statistical consistency across all scenarios

```lua
-- GenerateIVs Handler

  Action = "CalculateStats",
  SpeciesId = "number",

  Nature = "string",
  Timestamp = "number"
}
Response: {
  Action = "SaveState",
  Data = {
    stats = {hp, atk, def, spatk, spdef, speed},
    modifiers = {}  -- Applied modifiers
  },
  ProcessId = "string",
  Timestamp = "string"
}

-- GainEVs Handler
Request: {
  Action = "GainEVs",
  PokemonId = "string",
  EVYield = "string",    -- JSON array of 6 values
  Multiplier = "number", -- Pokerus, items, etc.
  Timestamp = "number"
}
Response: {
  Action = "SaveState",
  Data = {
    evs = {hp, atk, def, spatk, spdef, speed},
    totalEVs = "number",
    capped = "boolean"
  },
  ProcessId = "string",
  Timestamp = "string"
}
```

### Technical Constraints
**Coding Standards** [Source: architecture/coding-standards.md]:
- Never use Lua's math.random() - ALWAYS use AO crypto module
- All stat calculations must match TypeScript Math.floor/Math.ceil exactly
- Nature multipliers must be exactly 0.9, 1.0, or 1.1 (implemented in 3.3)
- All AO message responses must include success boolean
- Battle RNG counter must increment for every random call

**Performance Constraints** [Source: architecture/tech-stack.md#Performance Constraints]:
- Execution Timeout: 5-second limit per message handler
- File Size Limit: 500KB maximum per process file
- Memory Constraints: Limited by AO network specifications
- Message Size: Practical limits on JSON payload size

**AO Runtime Specifications** [Source: architecture/tech-stack.md#AO Runtime Specifications]:
- Monolithic Design: All dependencies embedded in single file
- Handler Pattern: Use `Handlers.add()` with tag matching
- Available globals: `ao.send()`, `ao.id`, `Handlers`, `json`
- No `require()` statements allowed

### Security Requirements
1. **Input Validation**: All stat values must be validated for legal ranges (IVs: 0-31, EVs: 0-252 per stat, 510 total)
2. **Data Integrity**: Stat calculations must include checksums to prevent corruption
3. **Deterministic Behavior**: All random IV generation must use AO crypto module
4. **State Consistency**: Stat modifications must be atomic to prevent partial updates
5. **Rate Limiting**: Handle rapid stat recalculation requests without memory leaks
6. **Access Control**: Stat modifications should be owned by player addresses
7. **Mathematical Precision**: Preserve exact decimal calculations before final rounding
