### Component Specifications
[Source: processes/trainer-encounter-engine.lua]

**Gym Leader Generation Components:**
1. **Party Template Selector** - `getGymLeaderPartyTemplate(wave, gameMode)`
   - Input: wave (number), gameMode (string)
   - Output: party template ID
   - Logic: Wave-based progression (≤20, ≤30, ≤60, ≤90, >90)

2. **Specialty Type Filter** - `filterSpeciesByType(speciesPool, specialtyType)`
   - Input: species pool (table), specialty type (number)
   - Output: filtered species list
   - Logic: Include only Pokemon with matching primary or secondary type

3. **Tera Mode Configurator** - `configureGymLeaderTera(wave, partySize)`
   - Input: wave (number), party size (number)
   - Output: AI configuration with Tera mode
   - Logic: Wave ≥100 → INSTANT_TERA on last party member, else NO_TERA

4. **Badge Reward Generator** - `generateBadgeReward(gymLeaderName)`
   - Input: gym leader name (string)
   - Output: badge metadata
   - Logic: Map gym leader name to badge name and icon

**Elite Four Generation Components:**
1. **BST Filter** - `filterSpeciesByBST(speciesPool, minBST)`
   - Input: species pool (table), minimum BST (number)
   - Output: filtered species list
   - Logic: Include only Pokemon with base stat total ≥460

2. **Sequential Progression Validator** - `validateEliteFourProgression(memberIndex, victories)`
   - Input: member index (1-4), victories count (number)
   - Output: boolean (can proceed)
   - Logic: Cannot skip members, must defeat in order

3. **Smart Tera AI** - `createSmartTeraAI(party)`
   - Input: party data (table)
   - Output: AI configuration
   - Logic: SMART_TERA mode, strategic timing based on matchup

4. **Championship Validator** - `validateChampionshipEligibility(eliteFourVictories)`
   - Input: Elite Four victories (number)
   - Output: boolean (can battle Champion)
   - Logic: All 4 Elite Four members must be defeated

### Technical Constraints
[Source: docs/architecture/tech-stack.md, Story 16.3]

**AO Runtime Constraints:**
- **Execution Timeout**: 5-second limit per message handler
- **File Size Limit**: 500KB maximum per process file
  - Current: trainer-encounter-engine.lua is 46KB (9.3% of limit)
  - Headroom: 454KB available (91% remaining for gym/Elite Four logic)
- **Monolithic Design**: All dependencies embedded in process file
- **Handler Pattern**: Use `Handlers.add()` with tag matching, one action per handler
- **Deterministic RNG**: Use LCG implementation (no math.random)
- **Message Protocol**: JSON-encoded data with structured ao.send() responses
- **Timestamp Handling**: CRITICAL - Use msg.Timestamp, NEVER os.time()
- **Error Handling**: Direct validation with ao.send() error responses, avoid unnecessary pcall
- **Tag Values**: All tag values MUST be strings: tostring(number), "true"/"false" for booleans

**Performance Considerations:**
- Gym leader generation: Expect <1s execution (5 Pokemon max at wave ≤90, 6 at wave >90)
- Elite Four generation: Expect <2s execution (6 Pokemon with BST filtering)
- Species/move lookups: Async with 3-retry exponential backoff (100ms, 200ms, 400ms)
- Tera mode calculation: Minimal overhead (simple threshold check)

**Dependencies:**
- External processes: pokemon-species-db, moves-database (existing from Story 3.1, 5.1)
- Internal data: trainer-data-engine (party templates, trainer configs from Story 16.2)
- Retry logic: 3 attempts with exponential backoff, 3s timeout, 60s failure cache
