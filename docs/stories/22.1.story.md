### Data Models

**DexEntry Structure** [Source: src/@types/dex-data.ts]
```lua
-- DexEntry represents all discovery data for a single species
{
  seenAttr = 0n,        -- Bitmasked bigint: forms, genders, variants, shiny seen
  caughtAttr = 0n,      -- Bitmasked bigint: forms, genders, variants, shiny caught
  natureAttr = 0,       -- Bitmask: all 25 natures encountered (bit 0 = Hardy, bit 1 = Lonely, etc.)
  seenCount = 0,        -- Total number of times species has been seen
  caughtCount = 0,      -- Total number of times species has been caught (captured)
  hatchedCount = 0,     -- Total number of times species has been hatched from egg
  ivs = {31,31,31,31,31,31}, -- Best IVs encountered for this species [HP, ATK, DEF, SPATK, SPDEF, SPD]
  ribbons = {}          -- RibbonData for ribbons earned by this species
}
```

**DexAttr Flags** [Source: src/enums/dex-attr.ts]
```lua
-- DexAttr enum for attribute bitmasking (bigint operations)
-- NOTE: Lua 5.3+ has native 64-bit integer support, use integer literals for bitmasking
local DexAttr = {
  NON_SHINY = 1,        -- 1n in TypeScript (bit 0)
  SHINY = 2,            -- 2n in TypeScript (bit 1)
  MALE = 4,             -- 4n in TypeScript (bit 2)
  FEMALE = 8,           -- 8n in TypeScript (bit 3)
  DEFAULT_VARIANT = 16, -- 16n in TypeScript (bit 4)
  VARIANT_2 = 32,       -- 32n in TypeScript (bit 5)
  VARIANT_3 = 64,       -- 64n in TypeScript (bit 6)
  DEFAULT_FORM = 128    -- 128n in TypeScript (bit 7)
  -- Additional form bits continue for species with multiple forms
}

-- Bitmasking operations (Lua 5.3 supports 64-bit integers natively)
-- seenAttr = seenAttr | DexAttr.SHINY  -- OR operation to add attribute
-- hasShiny = (seenAttr & DexAttr.SHINY) ~= 0  -- AND operation to check attribute
```

### API Specifications

**Handler: RegisterSeen** [Source: src/system/game-data.ts#setPokemonSeen]
- **Trigger Tag**: `Action = "RegisterSeen"`
- **Required Parameters**: `msg.SpeciesId`, `msg.Data` (JSON with form, gender, shiny, variant, isTrainer flag)
- **Response**: Registration confirmation with updated dex entry and statistics
- **Workflow**: Validate species → Extract attributes → Update seenAttr → Increment seenCount → Update game stats
- **Special Cases**: Mystery encounters with preventGameStatsUpdates flag, trainer battles skip legendary/mythical stats
- **Example**:
  ```lua
  -- Request
  {
    Action = "RegisterSeen",
    SpeciesId = "150",  -- Mewtwo
    Data = json.encode({
      formIndex = 0,
      gender = -1,  -- Genderless
      shiny = false,
      variant = 0,
      isTrainer = false,
      preventStatsUpdate = false
    })
  }

  -- Response
  {
    Action = "SaveState",
    Success = "true",
    Data = json.encode({
      speciesId = 150,
      registered = true,
      newAttributes = {"NON_SHINY", "DEFAULT_FORM"},
      dexEntry = {...},
      statsUpdated = {
        pokemonSeen = 1,
        legendaryPokemonSeen = 1  -- or subLegendaryPokemonSeen for sub-legendary species
      }
    })
  }
  ```

**Process Integration Pattern** [Source: docs/architecture/tech-stack.md#process-communication-protocol]
```lua
-- New pokedex-registration-engine.lua process
-- Registration pattern: handle seen/caught events and update dex data

local json = require("json")

-- DexAttr constants for bitmasking
local DexAttr = {
  NON_SHINY = 1,
  SHINY = 2,
  MALE = 4,
  FEMALE = 8,
  DEFAULT_VARIANT = 16,
  VARIANT_2 = 32,
  VARIANT_3 = 64,
  DEFAULT_FORM = 128
}

-- Helper functions for registration logic
local function registerSeen(speciesId, attributes, dexData, gameStats)
  local entry = dexData[speciesId] or createDexEntry()
  entry.seenAttr = entry.seenAttr | attributes.dexAttr
  if attributes.incrementCount then
    entry.seenCount = entry.seenCount + 1
    gameStats.pokemonSeen = gameStats.pokemonSeen + 1
  end
  return entry
end

local function registerCaught(speciesId, attributes, dexData, gameStats, starterData)
  local entry = dexData[speciesId] or createDexEntry()
  entry.caughtAttr = entry.caughtAttr | attributes.dexAttr
  entry.natureAttr = entry.natureAttr | (1 << (attributes.nature + 1))
  -- Form unlock logic
  -- Ability unlock logic
  -- Count updates
  return entry
end

-- Handler registration (individual handlers for each action)
Handlers.add("register-seen",
  Handlers.utils.hasMatchingTag("Action", "RegisterSeen"),
  function(msg)
    local speciesId = tonumber(msg.SpeciesId)
    if not speciesId then
      ao.send({
        Target = msg.From,
        Action = "Error",
        Error = "SpeciesId required"
      })
      return
    end

    local data = json.decode(msg.Data or "{}")
    local result = registerSeen(speciesId, data, dexData, gameStats)

    ao.send({
      Target = msg.From,
      Action = "SaveState",
      Success = "true",
      Data = json.encode(result)
    })
  end
)

-- Additional handlers for caught registration, progress tracking, validation
```

### Technical Constraints

**AO Runtime Constraints** [Source: docs/architecture/tech-stack.md#performance-constraints]
- Execution Timeout: 5-second limit per message handler
- File Size Limit: 500KB maximum per process file
- Estimated Process Size: ~35-45KB for registration logic
- Memory Constraints: Limited by AO network specifications
- Deterministic Execution: Consistent registration behavior (no randomness)

**AO Compliance Requirements** [Source: docs/architecture/tech-stack.md#process-implementation-requirements]
- Monolithic Design: All registration logic in single file
- Handler Pattern: Use `Handlers.add()` with individual handlers per action (no multi-action handlers)
- Error Handling: Direct validation and error responses, avoid unnecessary pcall usage
- **CRITICAL**: Never use pcall for simple data access (table lookups, parameter validation)
- **CRITICAL**: Use pcall ONLY for operations that genuinely might fail (external JSON parsing from untrusted sources)
- Available Globals: ao.send(), ao.id, Handlers, json, standard Lua (string, table, math)

**Forbidden Operations** [Source: CLAUDE.md#ao-process-implementation-guidelines]
- `require()` - No external module loading (except require("json") which is permitted)
- `os.time()` - Use `msg.Timestamp` instead
- `io` - No file system access
- `debug` - Debug library unavailable
- Network operations - Only through ao.send()

**Coding Standards** [Source: docs/architecture/coding-standards.md]
- Functions: camelCase (e.g., `registerSeen()`, `calculateProgress()`)
- Variables: camelCase (e.g., `dexEntry`, `completionPercentage`)
- Constants: UPPER_SNAKE_CASE (e.g., `MAX_SPECIES_COUNT`, `DEX_ATTR`)
- Tables/Objects: PascalCase (e.g., `DexAttr`, `DexEntry`)
- Files: kebab-case (e.g., `pokedex-registration-engine.lua`)
- All message responses must include Success tag: `Success = "true"` or `Success = "false"`

**Deterministic Behavior Requirements**
- All registration operations must be predictable and reproducible
- Attribute bitmasking must be consistent across executions (Lua 5.3 native 64-bit integers)
- Progress calculations must be verifiable and auditable
- Validation must be deterministic

**Bigint Handling** [Source: TypeScript uses bigint for seenAttr/caughtAttr]
- Lua 5.3+ provides native 64-bit integer support for attribute bitmasking
- Use integer literals and bitwise operators (|, &, ~, <<, >>) directly
- No need for external bigint libraries or string conversion
- Ensure all attribute values remain within 64-bit integer range

This story focuses on core Pokedex registration (seen/caught tracking):

2. **Seen Registration**: RegisterSeen handler marks species as seen with attribute flags
3. **Attribute Capture**: Extract form, gender, shiny, variant attributes

5. **Count Tracking**: Increment seenCount if not duplicate
6. **Statistics Update**: Update game statistics (pokemonSeen, legendary/mythical/shiny counters)
7. **Catch Event**: Player catches Pokemon
8. **Caught Registration**: RegisterCaught handler marks species as caught
9. **Form Unlocks**: Auto-unlock base form for battle forms, special species handling
10. **Nature/Ability**: Update natureAttr, unlock ability for starter species
11. **Progress Calculation**: Calculate completion percentage, milestone detection
12. **Response**: Return updated dex entry and statistics
