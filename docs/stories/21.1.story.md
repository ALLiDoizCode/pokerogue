## Dev Notes

### Previous Story Insights
**Stories 20.1-20.4** provided key learnings for Story 21.1:
- ✅ Monolithic process design with embedded data works well
- ✅ Individual handlers per action pattern is mandatory (no multi-action handlers)
- ✅ Direct error handling without unnecessary pcall is AO best practice
- ✅ Deterministic seeded RNG required for reproducible gacha pulls
- ✅ String conversion for all tag values (tostring() for numbers/booleans)
- ✅ Comprehensive parity testing catches behavioral differences early
- ✅ ADP v1.0 Info handler provides excellent self-documentation
- 💡 Strategy: Gacha mechanics should use stateless design with client-managed pull history
- 💡 Architecture Decision: Create new standalone `gacha-mechanics-engine.lua` process

### Architecture Decision: New Standalone Process
**Rationale for New Process:**
- Gacha mechanics are distinct from voucher economy (probability vs currency management)
- Gacha system requires complex probability calculations and pity tracking
- Separation allows focused testing of probabilistic behavior
- Process size management: gacha logic estimated ~60-80KB with embedded probability constants
- Future extensibility: gacha mechanics may expand with new gacha types

**Implementation Strategy:**
- Create new `processes/gacha-mechanics-engine.lua` process
- Define probability constants and tier thresholds embedded in process
- Implement handlers: PullEgg, GetGachaInfo, GetPityStatus, GetPullHistory
- Maintain stateless design with all pull history passed via GameState JSON
- Use deterministic seeded RNG for reproducible gacha behavior

### API Specifications

**Handler: PullEgg** [Source: Architecture requirements for AO message patterns]
- **Trigger Tag**: `Action = "PullEgg"`
- **Required Parameters**: `msg.GachaType` ("MOVE"|"LEGENDARY"|"SHINY"), `msg.VoucherType` ("REGULAR"|"PLUS"|"PREMIUM"|"GOLDEN"), `msg.RNGSeed` (deterministic seed), `msg.Timestamp` (for legendary rotation)
- **Optional Parameters**: `msg.PullHistory` (JSON with current pity counters)
- **Response**: Complete egg result with properties and updated pull history
- **Validation**: Voucher availability, gacha type validity, RNG seed format
- **Example**:
  ```lua
  -- Request
  {
    Action = "PullEgg",
    GachaType = "LEGENDARY",
    VoucherType = "PREMIUM",
    RNGSeed = "12345678",
    Timestamp = "1696800000",
    PullHistory = json.encode({
      totalPulls = 156,
      pullsSinceLastLegendary = 44,
      pullsSinceLastEpic = 12,
      pullsSinceLastRare = 3
    })
  }

  -- Response
  {
    Action = "SaveState",
    Success = "true",
    Data = json.encode({
      pullId = "pull_12345",
      timestamp = 1696800000,
      gachaType = "LEGENDARY",
      eggResult = {
        id = 98765432,
        tier = "EPIC",
        hatchWaves = 50,
        speciesId = 150,
        isShiny = true,
        variantTier = "RARE",
        eggMoveIndex = 3,
        hasHiddenAbility = false
      },
      pityTriggered = false,
      pullHistory = {
        totalPulls = 157,
        pullsSinceLastLegendary = 45,
        pullsSinceLastEpic = 0,  -- Reset after epic obtained
        pullsSinceLastRare = 0
      }
    })
  }
  ```

**Process Implementation Pattern** [Source: docs/architecture/tech-stack.md#process-implementation-requirements]
```lua
-- New gacha-mechanics-engine.lua process
-- Monolithic design with embedded probability constants

local json = require("json")

-- Gacha Constants (embedded from balance/rates.ts)
local GACHA_DEFAULT_COMMON_EGG_THRESHOLD = 52
local GACHA_DEFAULT_RARE_EGG_THRESHOLD = 8
local GACHA_DEFAULT_EPIC_EGG_THRESHOLD = 1
local GACHA_LEGENDARY_UP_THRESHOLD_OFFSET = 1

local EGG_PITY_LEGENDARY_THRESHOLD = 412
local EGG_PITY_EPIC_THRESHOLD = 59
local EGG_PITY_RARE_THRESHOLD = 9

local GACHA_DEFAULT_SHINY_RATE = 128
local GACHA_SHINY_UP_SHINY_RATE = 64

-- Gacha Types
local GachaType = {
  MOVE = "MOVE",
  LEGENDARY = "LEGENDARY",
  SHINY = "SHINY"
}

-- Egg Tiers
local EggTier = {
  COMMON = "COMMON",
  RARE = "RARE",
  EPIC = "EPIC",
  LEGENDARY = "LEGENDARY"
}

-- Helper functions for gacha mechanics
local function rollEggTier(gachaType, rngSeed) ... end
local function checkPityOverride(pullHistory, tierRolled) ... end
local function generateEggReward(tier, gachaType, rngSeed, timestamp) ... end
local function applyGachaTypeModifiers(baseRates, gachaType) ... end

-- Handler registration (individual handlers for each action)
Handlers.add("pull-egg",
  Handlers.utils.hasMatchingTag("Action", "PullEgg"),
  function(msg)
    local gachaType = msg.GachaType
    local voucherType = msg.VoucherType
    local rngSeed = msg.RNGSeed
    local timestamp = tonumber(msg.Timestamp)

    if not gachaType or not voucherType or not rngSeed or not timestamp then
      ao.send({
        Target = msg.From,
        Action = "Error",
        Error = "GachaType, VoucherType, RNGSeed, and Timestamp required"
      })
      return
    end

    -- Validate gacha type
    if not GachaType[gachaType] then
      ao.send({
        Target = msg.From,
        Action = "Error",
        Error = "Invalid GachaType: " .. gachaType
      })
      return
    end

    -- Parse pull history
    local pullHistory = json.decode(msg.PullHistory or "{}")

    -- Roll egg tier with pity check
    local tierRolled = rollEggTier(gachaType, rngSeed)
    local pityTriggered = false
    if pullHistory.pullsSinceLastLegendary then
      tierRolled, pityTriggered = checkPityOverride(pullHistory, tierRolled)
    end

    -- Generate egg reward
    local eggResult = generateEggReward(tierRolled, gachaType, rngSeed, timestamp)

    -- Update pull history
    pullHistory.totalPulls = (pullHistory.totalPulls or 0) + 1
    pullHistory.pullsSinceLastLegendary = (pullHistory.pullsSinceLastLegendary or 0) + 1
    pullHistory.pullsSinceLastEpic = (pullHistory.pullsSinceLastEpic or 0) + 1
    pullHistory.pullsSinceLastRare = (pullHistory.pullsSinceLastRare or 0) + 1

    -- Reset pity counter for obtained tier
    if tierRolled == EggTier.LEGENDARY then
      pullHistory.pullsSinceLastLegendary = 0
    elseif tierRolled == EggTier.EPIC then
      pullHistory.pullsSinceLastEpic = 0
    elseif tierRolled == EggTier.RARE then
      pullHistory.pullsSinceLastRare = 0
    end

    ao.send({
      Target = msg.From,
      Action = "SaveState",
      Success = "true",
      Data = json.encode({
        pullId = "pull_" .. tostring(timestamp),
        timestamp = timestamp,
        gachaType = gachaType,
        eggResult = eggResult,
        pityTriggered = pityTriggered,
        pullHistory = pullHistory
      })
    })
  end
)

-- Additional handlers for GetGachaInfo, GetPityStatus, GetPullHistory
```

### Technical Constraints

**AO Runtime Constraints** [Source: docs/architecture/tech-stack.md#performance-constraints]
- Execution Timeout: 5-second limit per message handler
- File Size Limit: 500KB maximum per process file
- Estimated Process Size: ~60-80KB for gacha logic with embedded constants
- Memory Constraints: Limited by AO network specifications
- Deterministic Execution: Use seeded RNG for reproducible gacha behavior

**AO Compliance Requirements** [Source: docs/architecture/tech-stack.md#process-implementation-requirements]
- Monolithic Design: All gacha logic in single file with embedded constants
- Handler Pattern: Use `Handlers.add()` with individual handlers per action (no multi-action handlers)
- Error Handling: Direct validation and error responses, avoid unnecessary pcall usage
- **CRITICAL**: Never use pcall for simple data access (table lookups, parameter validation)
- **CRITICAL**: Use pcall ONLY for operations that genuinely might fail (external JSON parsing from untrusted sources)
- Available Globals: ao.send(), ao.id, Handlers, json, standard Lua (string, table, math)

**Forbidden Operations** [Source: CLAUDE.md#ao-process-implementation-guidelines]
- `require()` - No external module loading (except require("json") which is permitted)
- `os.time()` - Use `msg.Timestamp` instead
- `math.random()` - Use deterministic seeded RNG instead
- `io` - No file system access
- `debug` - Debug library unavailable
- Network operations - Only through ao.send()

**Coding Standards** [Source: docs/architecture/coding-standards.md]
- Functions: camelCase (e.g., `rollEggTier()`, `checkPityOverride()`)
- Variables: camelCase (e.g., `gachaType`, `pullHistory`)
- Constants: UPPER_SNAKE_CASE (e.g., `GACHA_DEFAULT_COMMON_EGG_THRESHOLD`, `EGG_PITY_LEGENDARY_THRESHOLD`)
- Tables/Objects: PascalCase (e.g., `GachaType`, `EggTier`)
- Files: kebab-case (e.g., `gacha-mechanics-engine.lua`)
- All message responses must include Success tag: `Success = "true"` or `Success = "false"`

**Deterministic RNG Requirements**
- All probability calculations must use seeded RNG passed in message
- Never use math.random() - always use seeded RNG generator
- RNG seed format: string of digits (e.g., "12345678")
- Seed must be unique per pull for reproducibility
- Document RNG seed requirements in all handlers

- Statistical tests must validate tier distribution over 10,000+ pulls
