### Technical Constraints
[Source: Story 16.2 + architecture/tech-stack.md]
- **Execution Timeout**: 5-second limit per message handler
- **File Size Limit**: 500KB maximum per process file (currently 24KB each, ~48% of limit)
- **Monolithic Design**: All dependencies embedded in each process
- **Handler Pattern**: Use Handlers.add() with tag matching
- **Deterministic RNG**: Use LCG implementation from Story 16.2 (no math.random)
- **Message Protocol**: JSON-encoded data with structured ao.send() responses
- **Timestamp Handling**: CRITICAL - Use msg.Timestamp, NEVER os.time()
- **Error Handling**: Direct validation with ao.send() error responses, avoid unnecessary pcall
- **Tag Values**: All tag values MUST be strings: tostring(number), "true"/"false" for booleans
- **Inter-Process Communication**: Async message passing between trainer-data-engine ↔ trainer-encounter-engine ↔ species-lookup ↔ move-lookup

#### Pokemon Species Database API (pokemon-species-db.lua)
**Request Message - Get Species**:
```lua
ao.send({
    Target = "pokemon-species-db",
    Action = "get-species",
    Data = json.encode({ speciesId = 25 })  -- Pikachu
})
```

```lua
    Target = msg.From,

        t = { 12 },  -- Types (ELECTRIC)
```

```lua
}
```

### Error Handling Strategy

**Species/Move Lookup Failures**:
1. Retry failed lookups up to 3 times with exponential backoff (100ms, 200ms, 400ms)
2. Timeout threshold: 3 seconds per lookup attempt
3. After 3 failures, return error to client with Action="Error"
4. No fallback to random data (maintain deterministic behavior)
5. Cache lookup failures for 60 seconds to avoid repeated failures

**Error Response Format**:
```lua
ao.send({
    Target = msg.From,
    Action = "Error",
    Error = "Species lookup failed after 3 attempts",
    ErrorCode = "SPECIES_LOOKUP_TIMEOUT",
    RetryAfter = "60"
})
```
