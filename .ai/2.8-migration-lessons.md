## Key Lessons for Story 2.9

### 1. State Management is Critical
**Problem**: Processes maintain state across message calls (intended behavior)
**Impact**: Sequential tests accumulate state, breaking precision assertions
**Solutions**:
- Use unique entity IDs (PlayerId, BattleId, etc.) for independent tests
- Adjust test expectations to account for stateful behavior
- Consider creating state reset handlers for testing (if not AO-compliant)
- Group related tests that intentionally build state

### 2. Pattern Transformation Rules (VALIDATED ✅)
Successfully applied transformation from describe/it to linear:
```lua
-- ❌ OLD (describe/it)
describe("Feature", function()
    it("should work", function()
        assert.equals(expected, actual)
    end)
end)

-- ✅ NEW (linear)
print("📝 Test 1: Feature should work")
if actual == expected then
    print("✅ Test 1 passed")
else
    error("❌ Test 1 failed: expected X, got Y")
end
```

## Recommendations for Story 2.9 (now Story 2.10 - Consolidated Tests)

### For Consolidated Tests:
1. **Pre-Migration Analysis**: Map test files to actual process handlers
2. **Process Discovery**: Use handler inspection to identify which process owns which actions
3. **Test Grouping**: Group tests by process, not by original test file
4. **Integration Testing**: Some consolidated tests may require multiple process interactions

### For State Management:
1. **Document Statefulness**: Identify which processes maintain state vs stateless
2. **ID Strategy**: Use unique IDs (playerId, battleId, encounterId) for test isolation
3. **Expectations**: Adjust test assertions to match cumulative/stateful behavior
4. **Reset Handlers**: Consider if processes need test-only reset handlers (if AO-compliant)

### For Test Execution:
1. **Incremental Testing**: Test each migrated file immediately
2. **Debug Output**: Use print() statements liberally for state tracking
3. **Error Messages**: Provide detailed error messages showing expected vs actual
4. **Validation**: Run full test suite after each file to catch regressions

## Risks Identified for Story 2.10 (Consolidated Tests)

1. **Consolidated Process Ambiguity**: May not be clear which process handles which test
2. **Cross-Process Dependencies**: Tests may require coordination between processes
3. **State Accumulation**: More complex state interactions in event/narrative systems
4. **Time Overruns**: Revised estimates show 2-3x original time needed
